# SRPFreaks UI 설계

> 화면과 시각 규칙의 기준 문서. 데이터/API/보안은 `docs/DESIGN.md`를 따른다.
> 시안은 Claude Design 아티팩트("SRPFreaks 곡 카드 시안")에 있다. 이 문서는 시안에서 **정한 규칙을 글로 옮긴 것**이고, 시안과 다르면 이 문서가 우선한다.
> 시안의 곡 이름·점수·FC 표시·아티스트·BPM·노트 수·노트 성향 값은 **모두 임시 샘플**이다.

## 1. 기본 원칙

| 항목 | 규칙 |
|---|---|
| 우선순위 | **모바일 우선**(360px에서 먼저 확인). 서열표는 데스크톱용 표형을 따로 둔다 |
| 테마 | **다크 / 라이트** 두 가지. 색은 변수로 관리하고 테마별 값만 바꾼다 (4장) |
| 모양 (2026-10-18, 시안) | 터치 영역: 칩·토글·셀렉트·보조 버튼은 **높이 40~44px 이상**, 검색창은 48px. **필터 칩·선택 버튼은 예외**(2026-10-31): 필터 칩 모바일 36px · 마우스 데스크톱 30px, `전체/단일/…` 같은 선택 버튼 34px · 28px (서열표·곡 목록·마이페이지 필터 공통). 곡·채보 행은 데스크톱 48px(서열표 52px) · 모바일 56px(서열표 60px) 이상. 카드는 **모서리 16px**(`rounded-2xl`)에 안쪽 여백 16px. 달성 단계 칩(`StageBadge`)은 기존대로 **단계 색을 채운 배지**다(테두리형 시안은 적용했다가 되돌림). 헤더의 로그인·로그아웃 버튼과 테마 스위치는 높이를 키우지 않는다 |
| 고지 | 모든 화면 **하단**에 "비공식 팬 프로젝트"(굵게)와 "KONAMI와 무관" 문구(상단 띠는 없앴다)와 "곡·음원·게임 화면·명칭 등 모든 저작권과 상표 등 권리는 KONAMI에 있다" 문구 (시안 하단 문구는 이 문장으로 갱신 예정) |
| 헤더 메뉴 | **lg(1024px) 이상**은 헤더에 `이름 · 가로 메뉴 · 로그인 상태 · 테마 스위치`를 두고 ☰는 숨긴다. 가로 메뉴는 `홈 · 곡 · 유저 · 공지 · 건의 · 설명서 · (관리, ADMIN·ROOT만) · 마이페이지` 순서이고(곡 목록과 서열표를 `곡` 하나로 합쳤다. 곡은 마지막으로 본 탭(이 기기에 기억, `lib/song-tab.ts`, 처음은 `/table`)으로 가고, `/songs`·`/table`·곡 상세 어디서든 강조된다), 현재 화면은 배경 + 굵은 글자 + `aria-current="page"`로 강조한다(`DesktopNav`, 목록은 `lib/nav.ts`의 `DESKTOP_NAV_ITEMS`). **lg 미만**은 헤더에 `이름 · (sm 이상만) 로그인 상태 · 테마 스위치`만 두고, 메뉴는 하단 탭바의 `더보기` 시트가 맡는다(2026-10-20에 ☰ 슬라이드 메뉴를 없앴다). 아이콘은 `components/NavIcon.tsx`, 목록은 `lib/nav.ts` |
| 하단 탭바 | **lg 미만**에서만 화면 아래에 고정된다(`MobileTabBar`). `홈 · 곡 · 마이 · 더보기` 네 칸(아이콘 + 짧은 글자, 높이 56px + 하단 안전 영역)이다. `더보기`는 링크가 아니라 버튼이고, 누르면 탭바 위로 시트가 열려 `최근 플레이 가져오기(추천) · 공지 · 유저 · 건의 · 설명서 · 설정`을 보여 준다(바깥·Esc·링크·더보기 다시 누르기로 닫힘, 목록은 `lib/nav.ts`의 `MORE_ITEMS`). 시트 맨 아래에 `관리`(ADMIN·ROOT만)와 `로그인`/`로그아웃` 줄이 있다. 현재 탭은 굵은 글자 + `aria-current`로 알린다. 링크 이름은 전체 이름(`마이페이지`)이다. 탭바 높이는 CSS 변수 `--tabbar-h`로 두어 본문 아래 여백, `맨 위로` 버튼, 서열표 곡 검색 버튼, 토스트가 탭바 위로 올라가게 한다. 모달(dialog)은 탭바 위에 뜬다 |
| 푸터 배치 | 왼쪽 묶음: `비공식 팬 프로젝트` · KONAMI와 무관 · 권리 문구. 오른쪽 묶음(데스크톱은 오른쪽 정렬): 서열표 정보 제공 · 문의·삭제 요청 · 이용약관 · 개인정보 처리방침. 모바일은 두 묶음이 위아래로 쌓인다 |
| 출처 표기 | 서열표 정보 제공·설계자 `イズニャン (@trist_is)`를 푸터(모든 화면)와 서열표 화면 상단에 같은 문구로 표기한다. 링크는 새 탭(`noopener`)으로 연다. 값은 `lib/credit.ts` |
| 이미지 | 공식 로고는 쓰지 않는다. 재킷은 운영자 결정으로 쓸 수 있다(D21). 이미지가 없거나 꺼져 있으면 **단색 칸**(임시) 또는 생성 타일(8장). 이미지 칸은 기본 꺼짐이고 설정으로 켠다 (DESIGN.md 15장) |
| 달성률 표기 | 100.00은 `MAX`, 그 외 소수점 둘째 자리 (`86.78`) |
| 파트 표기 | `Guitar` / `Bass` (축약형 GT/BA는 쓰지 않는다) |
| 접근성 | 색만으로 의미를 전달하지 않는다 (글자/모양을 같이 쓴다). 본문 글자 대비 4.5 이상 |
| 글꼴 | 본문 Noto Sans KR, 숫자/영문 라벨 Chakra Petch |
| 문구 | 라벨은 **짧은 명사형**, 안내 문장과 오류 메시지는 일반적인 존댓말(`~합니다` / `~해요`)로 쓴다. 예: `속성은 SRN+ 옵션 사용 기준` / `사진은 인식하자마자 지우고, 저장하지 않아요.` |
| 용어 | 개수는 `n개`, 버전 항목은 `버전` (`초출 버전` 아님), 달성 단계는 `S / SS / FC / EXC` |

- **데스크톱 컨트롤 높이 (2026-10-31)**: 1024px 이상이면서 마우스 같은 정밀 포인터일 때(`compact`)만 버튼·칩·선택칸의 최소 높이를 44/40px → 36px로 줄인다(`globals.css` 한 곳). 휴대폰·태블릿 터치 높이는 44px 그대로. **뒤로 버튼**은 모든 화면에서 같은 정사각형(44px, compact 36px) + 가운데 화살표 아이콘(`components/BackArrow.tsx`).

## 2. 달성 단계 (C < B < A < S < SS < FC < EXC)

곡(채보)마다 **가장 높은 단계 하나만** 표시한다.

| 단계 | 조건 | 색 | 재킷 칸 테두리 (재킷 칸을 숨긴 동안은 쓰지 않는다) |
|---|---|---|---|
| `C` | 달성률 63.00 미만 | **색 미정** (시안 때 정한다. 낮은 단계라 차분한 색) | 없음 |
| `B` | 달성률 63.00 ~ 72.99 | **색 미정** | 없음 |
| `A` | 달성률 73.00 ~ 79.99 | **색 미정** | 없음 |
| `S` | 달성률 80.00 ~ 94.99 | 초록 `#4ADE80` | 없음 |
| `SS` | 달성률 95.00 이상 | 파랑 `#6EA0FF` | 없음 |
| `FC` | 풀콤보(0 miss) | 청록→보라 그라데이션 `#22D3EE → #C084FC` | 청록 `#22D3EE` |
| `EXC` | 달성률 100.00 (FC 포함) | 연금→주황→분홍 그라데이션 `#FFE27A → #FFB347 → #FF7EB6` | 금색 `#FFC24D` |

- **FC는 달성률만으로 알 수 없다.** 기록 저장 시 "FC 여부"를 따로 받는다 (`option_records.is_full_combo`). 달성률 100.00이면 자동으로 켠다.
- 판정 순서: EXC → FC → SS → S → A → B → C. (예: 96%이면서 FC면 `FC`만 표시) 기록이 있으면 항상 단계가 하나 있다 (D24).
- 단계 표시 글자는 어두운 색(`#10131A`)으로 둔다. 모든 단계 색에서 대비 7 이상.
- 기록이 없을 때만 아무것도 표시하지 않는다. A/B/C의 색은 정해지면 4장 색 변수에 추가한다(색만으로 구분하지 않고 글자 `A`/`B`/`C`를 같이 쓴다).

### 표시 위치
| 화면 | 표시 |
|---|---|
| 서열표 표형 | 행 왼쪽 4px 막대(FC/EXC는 세로 그라데이션) + 행 배경 틴트(왼쪽→오른쪽으로 옅어짐) + 곡명 옆 작은 표시 + 달성률 숫자 색. FC/EXC 행은 윗선 색도 바꾸고, EXC는 곡명도 금색 계열 |
| 서열표 모바일 한 줄 행 | 행 왼쪽 4px 막대 + 행 배경 틴트 + 곡명 아래 단계 표시 1개 + 달성률 숫자 색 (재킷 칸을 숨기기 전에는 FC/EXC가 재킷 칸 테두리였다) |
| 기록 목록 (곡 카드) | 카드 안 가로 표시 1개 (재킷 칸을 숨기기 전에는 FC/EXC가 재킷 칸 테두리였다) |

### 추후 후보 (시안에는 없음)
- 묶음 머리에 달성 현황 ("6/12 EXC · 9 FC")
- 묶음 안 **모든 채보가 같은 단계 이상**이면(예: EXC 1 + FC 1 + SS 2 → SS) 머리에 곡 카드와 같은 왼쪽 막대·배경을 준다. 한 곡이라도 S 미만이거나 기록이 없으면 없다. 서버가 준 칩 개수로 판정한다.
- 서열표 맨 위에 EXC/FC/SS/S 개수 요약
- 기록 저장 직후 해당 행이 한 번 반짝이는 효과

## 3. 서열표 (SRN+ 서열표)

### 구조
- **보기 상태는 주소에 저장 (2026-10-10)**: 서열표의 필터·정렬·평균 계산·페이지는 주소 쿼리(`/table?part=B&rec=상&pat=단일,복합&sort=rateDesc&zero=1&page=3`)에 둔다. 곡 상세에 갔다가 뒤로 와도, 새로고침해도, 링크를 공유해도 같은 화면이 나온다. 기본값(추천 상·중, 레벨 높은 순, 0% 미포함, 1페이지)은 주소에 쓰지 않고, 추천 전체는 `rec=all`. 알 수 없는 값은 기본값으로 돌린다. 바꿀 때 기록을 쌓지 않는다(replace). 펼침 상태는 저장하지 않는다.
- **기준 난이도**(스프레드시트의 기준 난이도 열, 0.1 단위)로 묶는다. 값이 클수록 위쪽(어려움).
- 데이터에서 실제 범위는 4.9 ~ 6.8. 값이 비어 있는 채보(미정)는 **서열표 화면에 나오지 않는다**(2026-10-10). 곡 목록과 곡 상세에만 `미정`으로 보인다.
- **서열표 본문의 묶음은 처음에 모두 닫혀 있다**(2026-10-10, 곡 목록의 레벨 폴더와 같다). 머리(`▸ 5.8  48개`, 달성 현황 칩, `기록 n/전체`, 평균)는 데스크톱에서는 닫혀도 모두 보이고 **모바일(768px 미만)에서는 닫힌 상태에 `제목 · n개 · 평균`만 보이며 칩과 `기록 n/전체`는 펼칠 때 보인다**(2026-10-18, 곡 목록의 레벨 폴더와 같은 규칙. 묶음 하나만 보는 묶음 화면은 항상 펼쳐 있어 늘 보인다), 제목 줄을 누르면 채보 목록이 펼쳐진다(`▾`, `aria-expanded`). 묶음 하나만 보는 묶음 화면은 접지 않고 항상 펼쳐 둔다.
- 묶음 제목은 `기준 난이도 · n개`로 쓴다 (예: `5.8  48개`, 손 이모지 없음).
- 제목 오른쪽에 **내 달성 현황**을 칩으로 붙인다: `EXC n · FC n · SS n · S n · S 미만 n` (0개인 칩은 흐리게). `S 미만`은 A/B/C 단계를 합친 것이고 **기록 없는 채보(미플레이)는 세지 않는다** (D24) + 맨 오른쪽 `평균 xx.xx%`.
- 그 아래 작은 글씨로 `기록 입력수/전체` (예: `기록 43/48`). **평균은 기록이 있는 채보만** 계산한다. 기록이 없으면 `–`.
- **평균 계산 토글** `0% 미포함 / 0% 포함` (기본 미포함). 미포함 = 기록 있는 채보만의 평균, 포함 = 기록 없는 채보를 0%로 넣은 평균(`미포함 평균 × 기록 수 ÷ 전체 수`). 기록이 하나도 없는 묶음은 미포함 `–`, 포함 `0.00%`. 토글은 화면 안의 모든 묶음에 한 번에 적용되고, 서열표 설명 아래(모바일) / 필터 줄(데스크톱)에 둔다. 선택 값은 화면 상태로만 두며 저장 여부는 구현 때 정한다.
- 각 곡은 가장 높은 단계 하나만 세므로 칩 숫자의 합은 기록 수와 같다 (기록 없는 채보만 어느 칩에도 안 들어간다).
- 묶음 안 정렬: 기본은 레벨 높은 순. 필터 영역의 `정렬` 선택 상자에서 레벨 높은 순 / 내 달성률 높은 순 / 내 달성률 낮은 순 / 곡명 순 / 추천도 순(상 → 중 → 하 → 없음)으로 바꾼다. 화면에서만 다시 늘어놓고 서버에 다시 묻지 않는다. 기록 없는 채보는 달성률 정렬에서 높은 순·낮은 순 모두 맨 뒤에 둔다.
- 서열표의 **달성률은 사용자 본인 기록**을 (곡, 난이도, 파트)로 연결해서 보여준다. 기록이 없으면 `–`.

### 표형 (데스크톱, 내용 폭 최대 1200)
- (2026-10-18) 데스크톱 필터는 파트 · 추천 · 속성 · 정렬 · 평균 계산을 **한 카드에 가로로** 놓고 넘치면 줄바꿈한다(모바일은 세로 접이식 패널 그대로). 열 너비는 랭크 70 · 채보 190 · 달성률 90px(곡 목록과 같다). 평균 계산 토글은 필터 카드 안에 둔다(곡 목록처럼 제목 줄로 옮기지 않았다).
열: 곡명 · 채보(`Guitar | MAS 9.80` 알약, 아래 "채보 알약") · 달성률 · 추천 · 속성 · 첫 버전
- 상단: 필터 칩 (파트 전체/Guitar/Bass, 추천 전체/상/중/하, 속성 전체/단일/복합/이중/삼중) + 기록 표시 범례
- **곡 검색 (2026-10-10)**: 서열표와 레이팅 상수 난이도 묶음 화면의 **우측 하단에 고정된 둥근 검색 버튼**(아이콘, `곡 검색`)을 둔다. ## 5. 레이팅 화면 (곡 카드)

- 맨 위 **레이팅 카드**: 합계(V×20의 합), 단일/복합·이중·삼중 소계, 플레이어 티어 칩, 다음 티어까지 진행 막대와 남은 점수. 마지막 티어(HSB)는 `최고 티어`로 표시한다.
- **승급 예고 (2026-10-19, 같은 날 제거)**: 요약 카드에 `가장 빨리 오르는 곡` 한 줄을 붙였다가, 기준을 정하기 어렵다는 이유로 **뺐다**. 카드는 `다음 티어까지 n점`까지만 보인다.
- 레이팅 카드 아래 접이식 **`목표 레이팅`**(2026-10-19, 처음에는 접힘, 내 화면에만): `목표 점수` 입력칸(정수 5자리까지·소수 둘째 자리까지, 입력하는 즉시 계산, 저장하지 않음)과 `{다음 티어} ({최소 점수})로 정하기` 버튼(최고 티어이면 없음). 목표가 지금 레이팅보다 높으면 `목표까지 +n점, 곡 k개를 올리면 달성합니다.`와 **올릴 곡 목록**(곡명(곡 상세 링크) · `Guitar | MAS 9.50` · `80.00% → 95.00%` · `+64.00`)을 보인다. 경로는 **내 레이팅 목록과 서열표의 목록 밖 채보**(레이팅 반영·속성이 있는 채보, 내 기록이 없으면 기록 없음)를 후보로 쓰고 **80 / 85 / 90 / 95% 구간 단위**로 올린다(2026-10-19 개정: 전에는 곡 수를 줄이려고 여지가 큰 곡을 95%까지 올려 비현실적이었다). 내 평균 난이도에 가장 가까운 폴더와 앞뒤 0.1 폴더(예: 5.4·5.5·5.6)의 곡을 먼저 쓰고, 그 폴더들의 기록 있는 곡 수·평균 달성률(서열표 기준)을 `내 평균 난이도 근처 폴더: 5.5 평균 87.40% (6곡) · …`로 보인다. 곡마다 지금 달성률 바로 위 구간부터 한 단계씩 돌아가며 올릴 폭이 작은 곡을 먼저 고르므로 곡·폴더·구간이 섞인다. 폴더 평균 달성률 바로 위 구간까지는 현실적이고, 그보다 높은 구간은 줄에 `도전` 글자를 붙여 맨 뒤에 둔다. 마지막 곡은 남은 점수만큼(달성률 소수 둘째 자리 올림)만 올리고, 같은 곡의 여러 구간은 한 줄로 합친다. **목록 밖 곡을 올려 단일 15 / 그 외 25 목록의 맨 아래 점수를 넘으면 그 곡이 목록에 들어오고 맨 아래 곡이 밀려난다.** 그래서 곡마다 늘어나는 점수는 밀려난 곡을 뺀 값이고, 들어오는 곡 줄에는 `목록 진입` 글자를, 기록이 없던 곡은 `기록 없음 → 80.00%`(최소 80%부터)를 보이며, 경로 아래에 `이 경로로 목록에서 밀려나는 곡`(위쪽 올릴 곡과 같은 카드 모양으로 곡명(곡 상세 링크)·`Guitar | MAS 9.50`·달성률·점수, 5곡까지 + `외 n곡`, 2026-10-22: 전에는 글자 줄이었다)을 보인다. 서열표는 열 때 받고(레이팅 예상 값과 같은 쿼리 키), 받지 못하면 `서열표를 불러오지 못해 레이팅 목록 안의 곡만 계산했습니다.`를 알리고 목록 안의 곡만으로 계산한다. 근처 폴더만으로 모자라면 전체 폴더로 넓히고 `근처 폴더만으로는 모자라서 다른 난이도의 곡도 포함했습니다.`를 알린다. 8곡을 넘으면 `외 n곡`으로 접는다. 쓸 수 있는 곡을 모두 95%로 올려도 모자라면 `모자란 점수`와 "더 높은 난이도의 곡을 목록에 넣어야 한다"를 알린다. 이미 넘은 목표는 `이미 목표를 넘었습니다.`만 보인다. 입력 오류 문구: `목표 레이팅을 입력해 주세요.` / `숫자로 입력해 주세요. 소수는 둘째 자리까지 입력할 수 있습니다.` / `0보다 큰 값을 입력해 주세요.`(`lib/rating-goal.ts`).
- 레이팅 카드 바로 아래 접이식 **`레이팅 예상 값`**(2026-10-10, D31, 처음에는 접힘, 내 화면에만): 단일은 1·7·15위, 복합·이중·삼중은 1·12·25위의 점수를 칸 머리에 상수표와 같은 색(`chart-cell`)으로 보이고, 아래에 **레이팅 상수 난이도별 필요 달성률**(높은 난이도 먼저, 낼 수 없으면 `불가`)을 줄로 보인다. 난이도 줄을 누르면 그 난이도의 채보(`곡명 · Guitar | MAS 9.50 · 내 단계/달성률`, 누르면 곡 상세)가 펼쳐진다. 맨 아래에 `표시한 달성률은 그 점수를 낼 수 있는 가장 낮은 값…95%…불가` 안내. **난이도 줄은 내 목록 채보의 평균 레이팅 상수 난이도에 가장 가까운 줄을 가운데로 5줄만 먼저 보이고**(위나 아래가 모자라면 반대쪽으로 채움), 아래 `더 보기 (n개)` ↔ `평균 난이도 근처만 보기`로 전부 펼친다(2026-10-10).

## 6. 곡 상세 (진입 경로에 따라 두 가지)

곡 상세는 **어디서 들어왔는지**에 따라 구성이 다르다. 두 화면 모두 곡 정보(재킷 칸, 곡명, 아티스트, 버전)를 갖고, **속성은 서열표에서 들어온 화면에만** 표시한다.

- **모바일 배치 순서 (2026-10-10)**: 한 열일 때 `곡 정보 → 내 기록(기록 등록 버튼) → 서열표 정보·다른 채보(또는 곡 정보 카드·레벨 정보) → 같은 난이도의 곡`. 기록 등록이 이 화면의 가장 큰 목적이라 위로 올렸다. 두 열(md 이상)은 예전처럼 왼쪽 정보 / 오른쪽 내 기록 + 같은 난이도의 곡이다. `뒤로` 버튼은 높이 36px 이상.

### 공통
- 상단 바: 뒤로 + `곡 상세`. 뒤로 가면 들어온 화면(곡 목록 또는 서열표)으로 돌아간다.
- 칩 줄(재킷 옆 아래쪽): 버전, 파트. 서열표에서 들어오면 선택된 채보 `MAS 9.80` · `Guitar`.
- **내 기록**: SRN+ 최고 기록 1줄(기록 없으면 `–`), 달성률 + 달성 단계 칩 + 날짜 (D25: 옵션별 5줄은 쓰지 않는다), 아래에 `기록 등록` 버튼 (10장의 등록·수정 화면을 연다).
  - **FC, EXC 기록은 서열표와 같은 그라데이션**을 쓴다: 달성률 숫자를 그라데이션 글자로, 단계 칩과 줄 왼쪽 막대도 같은 그라데이션 (FC `#22D3EE → #C084FC`, EXC `#FFE27A → #FFB347 → #FF7EB6`, 라이트는 2장의 라이트 값). S, SS는 숫자를 기본 글자색으로 두고 칩만 단색.

### 곡 목록에서 (모바일 / 데스크톱)
- 정보 카드 3개: BPM · 노트 수 · 버전.
- **레벨 정보** 표: 파트 · 난이도 · 레벨 · 기준 난이도(서열표 값) · 추천. 선택된 채보는 왼쪽 막대와 배경 강조. 곡의 모든 채보를 보여 준다. **속성은 표시하지 않는다.**
- 내 기록은 선택된 채보 기준 (`Guitar MAS 9.80 기준`).
- 데스크톱: 왼쪽 곡 정보·레벨 정보, 오른쪽 내 기록 (2단).

### 서열표에서 (모바일 / 데스크톱)
- 상단 오른쪽에 들어온 위치 칩 `SRN+ 서열표 · 5.3`.
- **속성 표시**: 곡 정보 영역의 **오른쪽 위**에 `속성 복합`처럼 작은 칩. 값은 시트의 속성 열(단일/이중/삼중/복합), 서열표에서 고른 채보 기준이다. **값이 없으면 칩을 숨긴다.** 속성은 SRN+ 옵션 사용 기준.
- 서열표에서 고른 **채보 하나**가 중심이다. 곡의 다른 채보는 `이 곡의 다른 채보 n개` 접힘 줄로 둔다.
- **서열표 정보** 카드: 기준 난이도 · 추천 · 레벨, 그 아래 `5.3 묶음 48개 · 내 평균 91.20%`와 묶음 안의 EXC / FC / SS / S 개수 (3장의 묶음 통계와 같은 값).
- 내 기록은 **SRN+ 줄을 강조**하고 `서열표는 SRN+ 기준`이라고 적는다.
- **같은 난이도의 곡**: 묶음 안의 모든 채보를 서열표 순서로 나열한다 (곡명, 파트·난이도·레벨, 내 달성 단계 또는 `기록 없음`). 지금 보는 채보는 배경과 `보는 중` 글자로 표시하고, 목록이 길면 상자 안에서만 스크롤한다(열릴 때 현재 채보 위치). 제목 오른쪽 `묶음 전체 보기`는 묶음 페이지로 간다. 눌러서 이동한다.
- **묶음 페이지** `/table/folder/{기준 난이도}` (예: `/table/folder/5.8`. 미정 묶음은 서열표 화면에서 뺐으므로 `undecided` 주소는 `묶음을 찾을 수 없습니다.`): 서열표의 묶음 하나(머리의 칩·평균·효과 + 채보 목록 + 기록 입력)를 따로 본다. `0% 미포함 / 0% 포함` 토글과 `서열표로` 돌아가기가 있다. **필터 칩**(2026-10-13): 서열표 본문과 같은 파트(하나) · 추천(여러 개) · 속성(여러 개) 칩을 둔다. 서열표 본문과 달리 **처음에는 필터가 없고**(묶음 전체) 화면에서 건다(서버 묶음 API가 없어서). 머리의 개수·단계 칩·평균은 걸러진 채보 기준으로 다시 계산하고, 맞는 채보가 없으면 `조건에 맞는 채보가 없습니다.`를 보인다. 난이도 이동 막대는 묶음 전체 기준 그대로다. 맨 위에 **난이도 이동 막대**(2026-10-10): `‹ 5.6 · 5.7 · 5.8 ›`(왼쪽이 낮은 난이도, 가운데에 지금 난이도와 `기록 n/전체`, 끝이면 그쪽 버튼 없음)와 그 아래 **난이도 칩 띠**(낮은 것부터 모든 난이도, 칩마다 `n/전체`, 지금 칩은 강조 + 열 때 보이는 자리로 맞춤, 완료는 글자 색)가 있다. 이동은 모두 주소를 **갈아 끼운다(replace)**: 난이도를 눌러 갈 때마다 뒤로 가기 기록이 쌓이지 않아 뒤로 가기 한 번이 서열표/곡 상세다. 없는 주소는 `묶음을 찾을 수 없습니다.`
  - **레이팅 반영 기준 (2026-10-27)**: 로그인했으면 난이도 이동 막대 아래에 한 줄 `이 구간은 단일 85% · 그 외 90% 이상이면 레이팅에 반영돼요.`. 홈 진행도 카드의 `N% 이상이면 레이팅에 반영돼요`와 같은 계산(`lib/rating-threshold.ts`, 내 목록 맨 아래 점수를 80/85/90/95로 올림)을 목록별로 나눠 보인다. 그 목록이 덜 찼거나 이 묶음에 그 속성의 채보가 없으면 그쪽은 빼고, 둘 다 없으면 줄을 그리지 않는다. 비로그인은 보이지 않는다.
- 데스크톱: 왼쪽 곡 정보·서열표 정보·다른 채보, 오른쪽 내 기록·같은 난이도의 곡.

> 노트 수는 채보마다 다르다. 채보를 선택하면 노트 수와 속성이 그 채보 기준으로 바뀐다. (시안은 Guitar MAS 9.80이 선택된 상태)

## 9. 곡 목록 (전체 곡)

### 구조
- 처음 진입하면 **레벨 폴더** 목록이 보인다. 폴더는 0.5 단위: `9.50 ~ 9.99`, `9.00 ~ 9.49`, … `1.00 ~ 1.49` (인게임 폴더와 같은 구간). 레벨이 높은 폴더가 위.
- 폴더 제목: `범위` + `n개` + (EXC/FC/SS/S 개수 칩) + `평균 xx.xx%` + 펼침 화살표. 폴더 이모지는 쓰지 않는다. 데이터가 없는 폴더는 흐리게 표시한다.
- 폴더 평균도 서열표와 같은 **`0% 미포함 / 0% 포함` 토글**을 쓴다 (3장 참고). 토글은 필터 아래·폴더 목록 위(모바일) / **`곡 목록` 제목 줄 오른쪽 끝**(데스크톱, 2026-10-18).
- 모바일은 접힌 상태에서 `제목 · n개 · 평균 · ▾` 한 줄, 펼친 폴더에만 칩과 `기록 n/전체`를 보인다. 데스크톱은 한 줄에 모두 보인다.
- 폴더를 펼치면 안에 **0.05 단위 하위 폴더**(`9.50 ~ 9.54`, `9.55 ~ 9.59` …)가 레벨 높은 순으로 나온다. 하위 폴더도 같은 제목 줄(범위 · n개 · 칩 · 평균)이고, 눌러서 펼치면 채보 행이 나온다. 채보가 없는 하위 폴더는 만들지 않는다.
- 폴더 안은 **채보 단위** 행이다 (한 곡의 MAS와 EXT는 각자 레벨 폴더에 들어간다).
  - 모바일 행: 곡명 · `Guitar MAS 9.99` 칩 + 랭크 (버전은 행에 보이지 않는다)
  - 데스크톱 행: 곡명 · 랭크 · 채보 · 달성률. 채보 목록 위에 **열 머리글 줄**(`곡명 랭크 채보 달성률`)이 있고, 열 너비는 랭크 70 · 채보 190 · 달성률 90px(달성률 글자는 모바일보다 한 단계 크다). 머리글은 장식이라 화면 읽기 프로그램에는 숨긴다(2026-10-18)
- 폴더 안 더 보기: 모바일은 `더 보기`(20개씩 이어 붙임), 데스크톱은 폴더 안 페이지 번호.

### 검색과 필터
- 검색창은 항상 보인다 (한글 · 일본어 · 로마자). (2026-10-25) 검색어가 있으면 검색창 아래에 **바로가기 후보**(맞는 채보 8개까지, 곡명 · 채보 알약 · 내 기록)가 나오고 누르면 곡 상세로 바로 간다. 후보는 폴더를 펼치지 않아도 곡을 찾는 지름길이고, 아래 폴더 목록은 같은 검색어로 그대로 걸러진다. 맞는 채보가 없으면 후보 목록은 그리지 않는다. 우측 하단에 서열표와 같은 고정 검색 버튼이 있고 누르면 이 검색창으로 포커스가 옮겨 간다. 검색하거나 필터를 쓰면 **폴더는 그대로 두고** 조건에 맞는 채보만으로 폴더별 개수·칩·평균이 다시 계산된다(맞는 채보가 없는 폴더는 사라진다). 폴더를 펼쳐 받는 채보 목록도 같은 조건이다. 조건은 주소 쿼리로 유지한다 (`/songs?q=…&part=G&diff=MAS`). 검색창을 비우고 필터를 초기화하면 전체로 돌아온다. 폴더는 10개씩 페이지로 나눈다(`이전 · 1 / 3 · 다음`).
- 필터: 파트(전체/Guitar/Bass), 난이도(ADV/EXT/MAS 다중, BAS는 쓰지 않는다), 버전. 속성 필터는 두지 않는다.
- 전체 곡 목록에는 **속성을 표시하지 않는다** (칩·열·필터·안내 문구 모두 없음). 속성은 서열표 목록과 서열표에서 들어온 곡 상세에만 둔다.
- 데스크톱은 **검색창과 필터를 한 카드의 한 줄**(`검색창 · 파트 · 난이도 · 버전 · 초기화`)에 두고 토글 칩을 그대로 보인다(2026-10-18). 모바일은 검색창 옆 `필터` 버튼 하나만 두고, 누르면 아래에서 올라오는 시트에 모든 필터를 모은다 (`초기화`, `결과 보기 · n개`). 적용 중인 필터 개수는 버튼에 `필터 3`처럼 표시한다.
- **구현 (2026-10-08, 시안과 다른 점)**: 모바일 필터는 시트 대신 **접이식 패널**이다(서열표 필터와 같은 방식, `결과 보기` 버튼 없이 바로 반영). 폴더 안 `더 보기`는 모바일·데스크톱 모두 20개씩 이어 붙이는 방식이고 페이지 번호는 없다. 폴더 머리는 서열표 묶음처럼 폴더의 모든 채보가 같은 단계 이상이면 막대·배경을 준다. 조건 주소 코드는 `part=G|B`, `diff=BAS,ADV,EXT,MAS`(쉼표), `ver=버전`, `q=검색어`. 주 메뉴 맨 앞 `곡 목록`과 홈 바로가기에서 들어온다. 곡 상세 링크는 `/songs/{곡 id}?from=songs&chart={채보 id}`.

- **배치 (2026-10-31)**: 제목 줄에는 `곡 목록`과 `곡 등록`만 둔다. 데스크톱은 한 카드 안에 두 줄 — 1줄 `검색창 · 평균 계산 · 개수`, 2줄 `파트 · 난이도 · 버전 · 초기화`. 모바일은 검색 줄 아래에 `평균 계산 · 개수` 한 줄, 필터는 `필터` 버튼으로 펼친다.

- 모바일(768px 미만)은 아래에서 올라오는 시트(높이 90%까지, 손잡이 막대), 데스크톱(md 이상)은 폭 448px 가운데 창이다. 두 환경 모두 한 칸이고, 입력 폼 위에 `이 채보의 내 기록` 목록이 들어간다(2026-10-18에 문서를 코드에 맞춤. 예전 문서의 2열 구성은 만든 적이 없다). 곡 검색 창(시트 85%·데스크톱 폭 512px)과 ROOT·ADMIN 편집 창도 같은 분기다. 확인 창(`ConfirmDialog`)은 화면 폭과 상관없이 항상 가운데(폭 22rem)이고, 헤더 메뉴는 lg 미만에서 오른쪽 슬라이드다(lg 이상은 가로 메뉴).
- 등록과 수정은 같은 화면이다. 제목만 `기록 등록` / `기록 수정`이고, 수정에는 **이 기록 삭제**(붉은 글자)가 붙는다.
- 입력 순서: 곡·채보(채보 변경) → 달성률 입력 + **달성 표시 미리보기**(자동 계산) → 풀콤보(0 miss) → 플레이 날짜(기본 오늘) · 메모(선택) → 취소 / 저장
- 달성률 입력칸은 **소수점 없는 정수 0~10000**만 받고(숫자 이외 글자는 입력되지 않는다, 2026-10-21) 저장할 때 ÷100으로 소수점을 자동으로 찍는다(`9971` → 99.71, `10000` → 100.00). **정확히 세 자리**(앞자리가 0이 아닌)는 `96.5`를 점 없이 `965`로 치는 습관을 받아 주려고 끝에 0을 붙여 읽는다(`965` → 96.50, 단 `100`은 100.00). 1~2자리와 4~5자리, 앞자리가 0인 글자(`0965` → 9.65, `050` → 0.50)는 그대로 100분의 1 단위로 읽는다. 수정 창은 1.00~9.99%를 `0500`처럼 네 자리로 채워 돌려줘서 열었다 저장해도 값이 바뀌지 않는다. 칸 아래에 `0 ~ 10000 정수 · 소수점은 자동으로 찍힙니다 (예: 9971 → 99.71, 세 자리는 965 → 96.50)`와 입력 중 `달성률 99.71(으)로 저장됩니다`를 보인다. 서버·DB는 그대로 0.00~100.00이다. 100.00이면 풀콤보를 자동으로 켠다.
- **예상 점수 (2026-10-10)**: 서열표·서열표 묶음·서열표에서 들어온 곡 상세에서 입력창을 열면 달성률 아래에 `예상 점수 · 레이팅 상수 난이도 6.0`과 점수를 보인다. 달성률을 입력하는 즉시 계산하고(저장하지 않는 미리보기, 설명서와 같은 식), 점수 글자는 17장의 티어 색과 빛 규칙을 쓴다. 레이팅 상수 난이도가 미정이거나 서열표에 없으면 이 줄을 그리지 않고, 달성률이 비었거나 범위 밖이면 `–`를 보인다. 레이팅 반영 스위치·속성 제외 여부와는 별개의 채보 점수다.
- **이 채보의 내 기록** 목록 (창 안, 폼 위): 달성률 · 단계 칩 · 날짜. 안내 `기록은 본인만 등록·수정·삭제. 수정하면 목록과 스킬에 바로 반영`. 모바일에서는 곡 상세의 내 기록 줄이 같은 역할을 한다.
- **열리는 방식 (2026-10-10)**: 이 채보에 내 기록이 있으면 **달성률이 가장 높은 기록의 수정**으로 바로 열린다(서열표에 보이는 값이라, 새 기록으로 낮은 값을 넣어도 안 바뀌는 혼란을 막는다). 제목 줄 오른쪽 `새 기록 추가` ↔ `기존 기록 수정`으로 바꾼다. 기록 목록의 `수정`은 어느 기록이든 고친다(버튼 높이 36px 이상). 열면 **달성률 칸에 커서**가 간다. 입력한 값이 있으면 **창 바깥을 눌러도 닫히지 않는다**(취소·Esc는 닫는다). 취소는 창을 닫는다. **신규 우선 (2026-10-22)**: 이 채보에 내 기록이 있어도 선택 화면 없이 **빈 `기록 등록` 폼으로 바로 열린다**(안내: `새 기록을 등록합니다. 기존 기록은 그대로 남습니다.`). 고쳐야 할 때는 제목 줄 `기존 기록 수정`(가장 높은 기록으로 전환) 또는 기록 목록의 `수정`을 누르고, 수정 중에는 `새 기록 추가`로 돌아온다. 기록이 없으면 첫 기록 안내와 함께 같은 등록 폼이다. 위의 "바로 수정으로 열린다"와 2026-10-16 분기(선택 화면)를 대체한다.
- **기록 삭제 (2026-10-10)**: `이 기록 삭제`를 누르면 **확인 창**(제목 `기록 삭제`, `이 기록을 삭제할까요? 되돌릴 수 없습니다.`, `취소` / `삭제`)이 위에 겹쳐 열린다. 취소에 먼저 포커스가 간다. 서버가 거절하면 확인 창을 닫고 폼 아래에 문구를 보인다.
- **완료 알림 (2026-10-10, 11일 확대)**: 요청이 성공하면 화면 아래에 `✓ 기록을 저장했습니다.`처럼 짧은 알림이 약 3초 떠 있다 사라진다(`role="status"`). **모바일은 아래 가운데, 데스크톱(md 이상)은 오른쪽 아래**다. 클릭은 막지 않는다. 기록 저장·수정·삭제뿐 아니라 설정·역할 변경·공지 등록/수정/삭제·곡·채보 수정/삭제·서열표 값 저장·닉네임·공개 설정·레이팅 기록·유저 기록 삭제·탈퇴에도 쓴다(곡 등록은 자체 완료 화면이 있어 제외). 정렬·필터로 줄이 화면 밖으로 가도 저장됐는지 알 수 있다.
- **등록과 수정 구분 (2026-10-16)**: 서버가 기록의 등록 시각(`createdAt`)과 마지막 수정 시각(`updatedAt`)을 응답에 준다. **플레이 날짜**(사용자가 입력)와 **등록·수정 날짜**(서버가 남김)는 다른 값이라 따로 보인다. 기록 창 제목 아래 한 줄에 `수정 중인 기록: 달성률 95.12 · FC · 등록 2026-10-12 · 수정 2026-10-14`(새 기록이면 `새 기록을 등록합니다. 기존 기록은 그대로 남습니다.`)를 보여 주고, 목록 줄은 `플레이 날짜` + `등록 …`(고쳤으면 `수정됨 · 등록 … · 수정 …`) 두 줄이다. 등록 직후 1분 이내의 차이는 수정으로 보지 않는다. 저장 버튼은 `수정 저장` / `새 기록 등록`, 완료 알림은 `기록을 수정했습니다. (91.25 → 95.00)` / `새 기록을 등록했습니다.`
- **레이팅 변화 안내 (2026-10-16)**: 저장 알림 뒤에 레이팅이 어떻게 바뀌었는지 덧붙인다 — `레이팅 +3.40 (10638.13 → 10641.53)`, 이 채보가 레이팅 목록에 **새로 들어갔으면** `· NEW 레이팅 목록에 새로 들어갔습니다.`, 목록 밖이면 `아직 레이팅 목록에는 들지 못했습니다.`, 점수 변화가 없으면 `레이팅은 그대로입니다.` 서버가 변화를 주지 못하면 저장 문구만 보인다.
- **예상 레이팅 (2026-10-16)**: 예상 점수 카드 안에 한 줄이 더 붙는다 — `예상 레이팅 +3.40`, 이 채보가 레이팅 목록(단일 15 / 그 외 25)에 **새로 들어가면** `· NEW 레이팅 목록에 새로 들어갑니다`(굵게), 점수가 같거나 낮으면 `레이팅 변화 없음`(목록 밖이면 `· 아직 레이팅 목록에는 들지 못합니다`). 내 레이팅 목록(서버 값, 레이팅 화면과 같은 쿼리)에 입력한 점수를 넣어 화면에서 계산하는 미리보기이고 저장 직후 알림에는 서버가 계산한 실제 값이 나온다. 구역은 서열표 속성으로 정한다(단일 / 그 외). 속성이 없거나 `레이팅 제외`·반영 끔이면 보이지 않는다. 지금 목록에 반영된 기록을 **낮게 고치는 경우**는 다음 기록이 대신 쓰여 알 수 없어서 보이지 않는다. 서열표 기준 난이도를 모르는 채보(최근 입력한 곡으로 옮긴 경우 포함)는 예상 점수 카드와 함께 나오지 않는다.
- **최근 입력한 곡 (2026-10-16)**: 기록 창 맨 위에 최근 입력(등록·수정)한 채보 최대 5곡이 가로로 이어진 버튼으로 나온다(곡명 + `Guitar MAS`). 지금 열린 채보와 같은 채보 중복은 뺀다. 누르면 창 안에서 그 채보로 바뀐다(창을 닫지 않는다). 입력 중인 값이 있으면 옮기지 않고 `입력 중인 값이 있습니다. 저장하거나 지운 뒤에 다른 곡으로 옮겨 주세요.`라고 알린다. 서열표 기준 난이도를 몰라 옮긴 뒤에는 예상 점수 미리보기가 나오지 않는다. 기록이 없으면 영역 자체가 없다.
- **서열표 점수 칩 (2026-10-16)**: 서열표 줄·카드의 레이팅 점수 칩을 누르면 그 채보의 기록 창이 바로 열린다(내 기록이 있으니 수정으로 열림). 칩은 누를 수 있는 영역만 사방 6px 넓힌다.
- **한 손 입력 모드 (2026-10-19)**: 기록 창 제목 줄의 `한 손 모드` 토글(`aria-pressed`)을 켜면 달성률 칸이 읽기 전용이 되고(소프트 키보드를 띄우지 않는다) 아래에 숫자 패드(0~9, `00`, 지우기)와 `FC` 버튼이 나온다. 패드는 소수점 없는 정수만 받고 10000을 넘는 입력은 무시하며(2026-10-21 개정), 10000(100.00)이면 FC가 자동으로 켜져 잠긴다. 켜 두면 풀콤보 체크박스는 FC 버튼으로 대신하고, 날짜·메모는 접힌 `날짜·메모 (선택)`으로 들어간다. 꺼 두면 기존 화면 그대로다. 설정은 이 브라우저의 localStorage(`srp.oneHandMode`, 토큰이 아닌 화면 설정)에만 저장한다.
- **세트리스트 자동 넘김 (2026-10-19)**: 한 손 모드가 켜져 있고 세트리스트에서 연 기록 창이면, 저장한 뒤 창을 닫지 않고 세트리스트의 **다음 미완료 곡**(지금 곡 뒤쪽 먼저, 없으면 앞쪽)으로 바뀌어 새 입력이 열린다. 더 입력할 곡이 없으면 평소처럼 닫는다. 삭제는 항상 닫는다. 다른 화면에서 연 기록 창은 바뀌지 않는다.
- 모든 기록은 같은 취급이다. 인증 칩, 증빙 사진, 이의제기는 없다 (보류, 13장).

### 10.0 저장 직후 결과 카드 (2026-10-20)
- 기록을 저장하면 창을 닫지 않고 **같은 창에서 결과 카드**를 보여 준다(`SaveResultCard`). 줄: 달성률 전→후(수정일 때만 전 값), 달성 단계(바뀌었으면 전→후 + `단계 상승`), 곡 점수 전→후(레이팅 상수가 있을 때, 점수는 레이팅 화면과 같은 티어 색), 레이팅 합계 증감과 전→후(후는 플레이어 티어 색), 레이팅 목록(`NEW`/목록에 있음/목록 밖 안내).
- 값은 저장하지 않고 서버 응답(`ratingChange`)과 입력한 달성률로 화면에서 계산한다. 새 기록 등록은 이전 값을 모르므로 전후 비교 없이 결과만 보인다.
- 버튼: `내 레이팅 보기`(/me?tab=rating), `다음 곡 입력`(창 닫기). 세트리스트로 이어 입력하는 흐름(저장 뒤 다음 곡으로 넘김)은 카드 없이 그대로 넘어간다. 토스트는 계속 뜬다(짧은 확인).

### 10.1 사진으로 입력 (D16)
- 기록 등록 시트 맨 위에 탭 `사진으로 입력 | 직접 입력`. 직접 입력 화면은 기존 그대로.
- **1단계 사진 선택** (모바일): 점선 사진 칸(촬영·앨범·캡처), 안내 4줄(사진은 인식 직후 지운다 / 플레이어 이름·ID는 읽지 않는다 / 결과는 저장 전에 확인·수정 / 하루 업로드 횟수 제한), `인식하기` 버튼 (사진을 고르기 전에는 비활성).
- **2단계 인식 결과**: 곡명도 읽는다. 곡이 정해지면 곡 칸에 곡명과 `인식됨` 표시, 오른쪽에 `바꾸기`. 인식된 칸(채보 난이도·레벨, 노트 옵션, 달성률)에도 녹색 `인식됨` 표시. 곡별 SKILL 일치 줄(`✓ 곡별 SKILL 189.42 · 계산값과 일치해요`, 불일치면 경고색), 풀콤보는 Miss 수로 자동. 버튼은 `다시 찍기` / `저장`.
- **인식 실패** (모바일 별도 시안): 읽지 못한 칸은 주황 점선과 `읽지 못함` 표시로 비우고 안내한다. 곡명은 `곡명을 읽지 못했어요. 한글, 일본어, 로마자로 검색해서 골라 주세요.`, 그 밖의 칸은 `입력해 주세요`. 필수 칸이 다 채워지기 전에는 `저장`이 비활성이다.
- 데스크톱은 왼쪽에 사진 끌어다 놓기 칸, 오른쪽에 같은 결과 칸.
- 문구: 안내 문장은 일반적인 존댓말로 쓴다 (예: `사진은 인식하자마자 지우고, 저장하지 않아요.`). 칩·버튼 같은 짧은 라벨은 명사형.
- 문구 규칙은 그대로: 짧은 명사형 라벨, 안내 문장은 존댓말.

### 13.1 노트 성향 그래프 (원래 7장)

슈퍼랜덤(SRN)·슈퍼랜덤플러스(SRN+)에서 어떤 패턴이 나오는지 보여주는 레이더 차트.

| 항목 | 내용 |
|---|---|
| 축 (6개, 위쪽부터 시계 방향) | 단일 · 고속 · 이중 · 삼중 · 지구력 · 테크닉 |
| 값 | 0 ~ 100 (백분율). 눈금 20 / 40 / 60 / 80 / 100 |
| 그리는 위치 | 값 0도 중심이 아니라 **반지름의 10% 지점**에 그린다 (`plot = 10 + 0.9 × 값`). 모든 값이 0이어도 작은 육각형이 남고, 거기서 바깥으로 뻗는다. 기준선(값 0)을 옅은 육각형으로 같이 그린다. 수치 표와 라벨은 실제 값 그대로 |
| 시리즈 | **SRN**(청록 `#2DD4BF`, 원 마커) 과 **SRN+**(분홍 `#F472B6`, 마름모 마커). 라이트는 `#0D9488` / `#DB2777` |
| 보기 전환 | SRN / SRN+ / 비교 (시안은 비교) |
| 아래 표 | 항목별 SRN %, SRN+ % 와 막대. 두 값이 다르면 행 강조 + SRN+ 값을 분홍으로 |

- 색만 쓰지 않는다: 시리즈는 마커 모양(원/마름모)과 아래 표의 숫자로도 구분된다.
- 시안의 값 (A.DOGMA, **임시**): 단일 60 · 고속 5 · 이중 50 · 삼중 0(SRN+는 20) · 지구력 30 · 테크닉 0 (테크닉은 값 입력 전이라 0)
- 값은 **ROOT와 ADMIN이 직접 입력**한다 (입력 화면은 미정). 데이터는 채보 × 옵션 × 항목으로 저장한다 (DESIGN.md 6장 `difficulty_profiles`).
- 구현 메모: 축이 늘어나면 각도는 `360 / 축 개수`로 계산한다. 축 이름/개수를 코드에 박지 않고 데이터로 받는다.

### 13.2 기록 등록의 증빙 사진과 인증 표시, 기록 상세, 이의제기, 신고, 관리자 처리 (원래 10장)

- 모바일은 아래에서 올라오는 시트, 데스크톱은 가운데 창(왼쪽 입력, 오른쪽 기록 상태).
- 입력 순서: 곡·채보(채보 변경) → 노트 옵션(NORMAL / RANDOM / SRN / RANDOM+ / SRN+) → 달성률 입력 + **달성 표시 미리보기**(자동 계산) → 풀콤보(0 miss) → 플레이 날짜(기본 오늘) · 메모(선택) → **기록 상태** 카드 → 취소 / 저장
- 달성률 입력칸은 **소수점 없는 정수 0~10000**만 받고(숫자 이외 글자는 입력되지 않는다, 2026-10-21) 저장할 때 ÷100으로 소수점을 자동으로 찍는다(`9971` → 99.71, `10000` → 100.00). **정확히 세 자리**(앞자리가 0이 아닌)는 `96.5`를 점 없이 `965`로 치는 습관을 받아 주려고 끝에 0을 붙여 읽는다(`965` → 96.50, 단 `100`은 100.00). 1~2자리와 4~5자리, 앞자리가 0인 글자(`0965` → 9.65, `050` → 0.50)는 그대로 100분의 1 단위로 읽는다. 수정 창은 1.00~9.99%를 `0500`처럼 네 자리로 채워 돌려줘서 열었다 저장해도 값이 바뀌지 않는다. 칸 아래에 `0 ~ 10000 정수 · 소수점은 자동으로 찍힙니다 (예: 9971 → 99.71, 세 자리는 965 → 96.50)`와 입력 중 `달성률 99.71(으)로 저장됩니다`를 보인다. 서버·DB는 그대로 0.00~100.00이다. 100.00이면 풀콤보를 자동으로 켠다.
- **기록 상태** 카드 (DESIGN.md 12장)
  - 미인증: `미인증` 칩 + `증빙 사진 첨부 (선택)` 버튼 + `오늘 n / 100장`. 안내 `증빙 사진을 첨부하면 인증 기록`
  - 첨부 후: `✓ 인증` 칩 + 파일명·용량·`30일 보관 후 삭제` + `변경 · 삭제`. 안내 `이의제기가 접수되면 관리자가 사진을 확인`
  - 하단 안내: `사진은 다른 사용자에게 보이지 않음. 사진 속 위치 정보(EXIF)는 제거 후 저장`
- 인증 상태는 색에 의존하지 않고 글자로 구분한다: `미인증`, `✓ 인증`, `✓ 관리자 확인`, `공식`.
- 데스크톱은 이미지 놓는 영역(드래그 앤 드롭)과 사진 미리보기를 오른쪽에 둔다.

#### 목록의 인증 표시
- 기록 목록(곡 카드) 위에 **전체 / 인증 / 미인증** 칩을 두고, 카드의 난이도 칩 오른쪽에 `✓ 인증` / `✓ 관리자 확인` 작은 뱃지를 붙인다. 미인증 카드는 뱃지 없음.
- 이의제기 버튼은 인증 기록 상세에 두고, `✓ 관리자 확인` 기록은 비활성화하고 이유를 적는다.

#### 기록 상세 / 이의제기 / 신고 / 관리자 처리
- **기록 상세**: 사용자·곡·난이도·옵션, 달성률과 달성 단계 칩, FC, 날짜, `기록 상태` 카드(인증 / 관리자 확인), 증빙 사진(썸네일, 누르면 원본), 버튼 `이의제기` · `사진 신고`.
- 인증 기록은 `2026-10-25까지 이의제기 가능 (D-n)`을 보여 주고, 사진은 로그인 사용자만 열람한다고 적는다. 관리자 확인 기록은 이의제기 버튼을 비활성화한다.
- **이의제기**: 사유 선택(사진과 기록이 다름 / 결과 화면이 아닌 사진 / 다른 사람의 사진 도용 의심 / 기타) + 설명. 한 기록에 한 사람당 1번만(기각 후 재접수 불가), 신고자 비공개, 다건·허위 반복 시 자동 제한, 비속어 사유 접수 불가, 오늘 n/10건 안내. 모바일은 바텀 시트, 데스크톱은 모달.
- **사진 신고**: 사유 선택(성과와 무관한 사진 / 부적절한 내용 / 개인정보 노출 / 기타). 3건 신고 시 자동 숨김 + 관리자 확인.
- **관리자 이의제기 처리**: 탭 `이의제기 / 신고 숨김 / 처리 완료`, 큰 사진과 기록 값을 나란히 놓고 확인 목록(곡·채보 / 달성률 / FC 일치)을 체크한 뒤 `일치 · 이의 기각` 또는 `불일치 · 이의 인정`.

### 13.3 스킬 화면의 인증 필터와 비율 (원래 5장)

### 14.z 홈 화면에 추가(PWA) (2026-10-20)
- 오락실에서 휴대폰으로 쓰는 사용자를 위해 **홈 화면에 추가**하면 주소창 없는 전체 화면으로 열린다(`app/manifest.ts`, 아이콘은 직접 만든 `SRP` 글자 아이콘 `public/icons`, 게임 로고·재킷은 쓰지 않는다).
- 상태 표시줄·주소창 색은 테마 바탕색에 맞춘다(`viewport.themeColor`). 노치 영역은 헤더의 `safe-area-inset-top`과 탭바의 `safe-area-inset-bottom`이 처리한다.
- **연결 끊김 안내**: 인터넷이 끊기면 헤더 아래에 `인터넷에 연결되어 있지 않습니다. 연결되면 다시 시도해 주세요.` 띠가 나타나고 연결되면 사라진다(`OfflineBanner`). 저장이 실패해도 입력한 값은 폼에 남는다.
- **화면 꺼짐 방지**: 기록 창이 열려 있는 동안만 Screen Wake Lock을 건다(`lib/wake-lock.ts`). 지원하지 않거나 거부돼도 조용히 넘어간다.
- **서비스 워커(오프라인 캐시)는 두지 않는다**: 기록·레이팅은 항상 서버 값이어야 하고 오래된 화면이 남는 사고를 피한다.

### 14.w 느린 망 대비 (2026-10-20)
- 조회가 실패한 자리에는 문구와 함께 **`다시 시도` 버튼**(`ErrorRetry`)을 둔다. 새로고침 없이 그 요청만 다시 보내고, 다시 보내는 동안에는 버튼을 잠근다. 폼 입력 오류에는 쓰지 않는다.
- 조회(GET)는 **15초** 안에 응답이 없으면 끊고 `응답이 늦어지고 있습니다. 잠시 후 다시 시도해 주세요.`로 알린다(`lib/api.ts`). **저장 같은 쓰기는 끊지 않는다**: 서버가 이미 처리했는데 화면만 실패로 보이면 중복 저장이 생길 수 있다.
- 자동 재시도: 네트워크·시간 초과·5xx만 두 번 더 시도하고, 4xx(없는 곡, 권한 없음)는 같은 답이라 바로 실패로 보여 준다(`app/providers.tsx`).
- 적용: 레이팅, 홈 레이팅, 곡 목록/폴더, 곡 상세, 서열표, 통계, 세트리스트·추천, 유저 목록, 건의 목록, 레이팅 기록. 관리 화면은 제외했다.

## 14. 홈 (대시보드)
- **로그인 전**: 서비스 소개, Google 로그인 안내, `로그인` 버튼, 서열표·레이팅·기록 입력 소개 카드(링크 아님. 각 화면은 로그인이 필요하다).
- **로그인 후** (위에서 아래로): `{닉네임}님의 홈`(닉네임이 없으면 `플레이어`) → **공지사항**(2026-10-19: 최근 3건, 아래) → **레이팅 요약 카드**(5장과 같은 카드, 누르면 레이팅 화면) → **서열표 진행도 카드** → 서열표·레이팅 바로가기.
- **진행도 카드**: 위에 `서열표 | 곡 목록` 탭(버튼 둘, 높이 44px, 기본은 서열표). 탭마다 같은 모양이다. ① **도넛**: 전체 채보 중 EXC/FC/SS/S/S 미만 비율을 호로 보여 주고(남은 부분 = 기록 없음), 가운데에 `xx%`와 `기록 n/전체`, 옆에 단계 배지(글자)+개수와 `S 미만`·`기록 없음` 개수. ② **다음 목표**: `SS 이상 n곡 → m곡까지 k곡 남음`(m은 다음 10곡 단위, 전체를 넘지 않음. 전부 SS 이상이면 숨김). ③ **칸 지도**(**sm(640px) 이상은 3열 카드, 640px 미만은 표형 1열**, 2026-10-20 시안 A. 모바일 표형: 머리글 `구간 · 달성 · EXC · FC · SS · S · S 미만`을 맨 위에 한 번만 두고 줄마다 구간(이름·`기록/전체`)·`xx%`·단계 개수 5칸(0은 `-`, 단계 색은 글자와 함께)·줄 아래 얇은 단계 비율 막대를 보이며, 줄 전체가 링크이고 숫자 앞에는 보이지 않는 단계 이름(sr-only)이 있다. 한 목록(ul)에서 CSS로 두 배치를 번갈아 보인다): 묶음 하나가 한 칸 — 이름, `xx%`, `기록/전체`, 단계 비율 막대. **sm(640px) 이상에서는 칸 오른편에 개수 칩이 두 줄(`EXC FC` / `SS S S 미만`)로 놓이고, 단계 비율 막대는 칸 아래에 전체 폭으로 깔린다**(넓어진 칸의 빈 자리를 채운다, 2026-10-18. 모바일은 위 표형 줄로 대신한다). 많이 채울수록 칸이 진하고, 기록이 모두 찬 칸은 막대 테두리와 이름 글자가 완료 색(`완료` 글자는 쓰지 않는다). ④ 평균 근처 구간 안내(**서열표 탭에서만** 보인다, 2026-10-27): 내 평균 난이도 ±0.1 안의 구간 중 기록 비율이 가장 낮은 칸(미정 제외)을 골라 `내 평균 6.1 근처인 6.0 구간을 채워 보세요. 85% 이상이면 레이팅에 반영돼요.` + `구간 보기` 링크. 범위 안에 비어 있는 채보가 없으면 숨긴다. 뒤 문장(`N% 이상이면 레이팅에 반영돼요.`)은 내 레이팅 목록의 맨 아래 점수(단일 15위·그 외 25위)를 넘는 데 필요한 달성률을 80/85/90/95 중 올림한 값이고, 두 목록 중 더 쉬운 쪽을 쓴다(`lib/rating-threshold.ts`). 목록이 덜 찼거나 어떤 달성률로도 못 넘거나 합친 `6.5 이상` 칸이면 이 문장만 뺀다. **평균을 알 수 없는 신규(기록 부족)에게는 이 안내를 두지 않는다**(기록이 적어 "어디가 비었는지"가 의미 없다, 예전 `가장 비어 있어요` 문구는 없앴다). 서열표 탭의 칸은 기준 난이도 0.1 단위(6.5 이상은 한 칸 `6.5 이상`)이고 **`미정` 묶음은 칸 지도·도넛 합계·다음 목표에서 뺀다**(서열표 화면과 같은 규칙, 2026-10-18). 누르면 묶음 페이지(`/table/folder/…`, 합친 칸은 `/table`), 곡 목록 탭의 칸은 레벨 폴더(0.5 단위, `9.50 ~ 9.99`)이고 누르면 `/songs`다(폴더마다 따로 주소가 없다). 숫자는 서버가 준 묶음/폴더 통계를 합치거나 비교한 값이다. 도넛과 막대는 장식(aria-hidden)이고 같은 값이 글자로 있다. 도넛 색은 단계 막대와 같고 EXC/FC 그라데이션은 SVG 때문에 `--ring-*` 변수로 따로 둔다. 한 탭이 실패하거나 서열표가 없어도 다른 탭은 그대로 쓴다.

## 16. 관리 (ADMIN · ROOT)
- 주 메뉴 맨 오른쪽에 `관리`가 ADMIN과 ROOT에게만 보인다(USER·비로그인에게는 없다). 설정 화면에도 같은 조건으로 `관리` 카드(`관리 화면` 링크)가 있다.
- `/admin`은 관리 메뉴다. **ADMIN**에게는 `곡 관리`(곡 목록으로)와 `서열표 관리`(서열표로)가, **ROOT**에게는 거기에 `사용자`, `설정`, `감사 로그`가 더 보인다. 아래 세 화면은 ROOT 전용이고 ADMIN이 주소로 들어가면 `권한이 없습니다.`만 보인다. 이 조건은 화면을 보이게 하는 것일 뿐이고 권한은 서버가 API마다 다시 검사한다.
- **감사 로그** `/admin/audit-logs` (ROOT): 최근 순 목록. 한 줄 = 작업 이름(`곡 등록`, `서열표 값 수정` …, 모르는 종류는 코드 그대로) + 날짜·시각(Asia/Seoul, `2026-10-27 22:40`, 2026-10-27부터) + 작업한 사람 닉네임(탈퇴했으면 `(탈퇴한 사용자)`, 이메일은 보이지 않는다) + 대상(`SONG #7`) + 세부 내용(2026-10-27부터 읽기 쉬운 글자: `KJY → HJY`, `제목: …`, 서열표 수정은 바뀐 칸만 `속성: – → 단일`. 아는 키는 화면 이름, 모르는 키는 그대로, 켜짐/꺼짐, 목록은 5개까지 `외 n개`. 마우스를 올리면 원문 JSON. 길면 자름). 30건씩 `이전/다음`. 위에 **작업 종류 선택 상자**(`전체` + 화면 이름이 있는 종류, 고르면 바로 적용)와 **검색 상자**(닉네임 또는 로그 내용·대상 번호, `검색`/엔터로 적용, 50자까지)가 있고 조건이 있으면 `초기화`가 보인다. 조건이 바뀌면 첫 페이지부터, 결과가 없으면 `검색 결과가 없습니다.`. 닉네임은 작업한 사람과 대상 유저 둘 다 찾는다.
- **설정** `/admin/settings` (ROOT): 설정 한 칸마다 이름·키·설명·입력칸·`저장`·`마지막 변경`(바꾼 사람, 날짜)이 있다. 숫자/정수/켬·끔/고르기/글자 종류에 맞는 입력이고, 바꾸기 전에는 `저장`이 꺼져 있다. 뻔한 실수(숫자 아님 등)는 화면이 먼저 막고, 레이팅 계산에 쓸 수 없는 값은 서버가 거절해 그 칸에 오류를 보여 준다. 레이팅 설정을 바꾸면 모든 사용자의 점수가 바로 달라진다는 안내가 맨 위에 있다. `ui.show_song_images`와 `contact.takedown_email`은 값만 저장하고 아직 화면에서 읽지 않는다.
- **사용자** `/admin/users` (ROOT): 가입 순 목록. 한 줄 = 닉네임(없으면 `(닉네임 없음)`) + 역할 이름 + 이메일 + `차단됨`(해당 시) + 가입일. ROOT 줄에는 변경 칸이 없고, 나머지 줄에는 역할 선택(`일반 사용자(USER)` / `관리자(ADMIN)`, ROOT는 고를 수 없다)과 `저장`이 있다. 바꾸기 전에는 `저장`이 꺼져 있다. 같은 줄에 `차단`(차단된 줄은 `차단 해제`) 버튼이 있고, 누르면 확인 창(`계정 차단` / `차단 해제`)을 거친 뒤 적용한다(D46, 2026-10-23). 서버가 거절하면 그 줄에 오류를 보여 준다. 10명씩 `이전/다음`. 목록 위에 검색 칸(닉네임 또는 이메일)과 `검색` 버튼이 있고, 검색을 누르면 첫 쪽부터 다시 보며 `초기화`로 전체 목록으로 돌아간다. 결과가 없으면 `검색 결과가 없습니다.`(2026-10-23).

## 17. 레이팅 설명서 (`/guide`)
- 로그인 없이 보는 정적 화면. 메뉴 `설명서`(헤더·모바일 슬라이드 메뉴)로 들어간다. 문구는 시안(모바일 보드)을 그대로 쓴다.
- 구성: 소개 → 한눈에 보기(SRN+ / 40채보 / 티어) → 포함 기준(**처음에 접힘**, 포함되는 채보 · 포함되지 않는 채보 · 고르는 방식 · 기록 관리) → 레이팅 상수표. `기록 관리` 카드 문구: `부정한 방법으로 입력한 기록은 운영자가 삭제할 수 있습니다.`(D29)
- 상수표: 레이팅 상수 난이도 7.0~4.9(행) × 달성률 70~95%(열)의 채보 점수(정수 반올림). **칸 색은 플레이어 티어 색**(2026-10-10): 곡 점수가 `티어 최소 점수 ÷ 40` 이상이면 그 티어다(40곡 모두에서 그 점수를 냈을 때 도달하는 티어, 예 Iridescent 9,500 ÷ 40 = 237.5점부터). 티어를 고르는 데는 반올림 전 점수를 쓴다. 칸 글자는 검정(`#000`)이고 모든 티어 색 위에서 대비 4.5 이상이다(Bronze는 글자가 놓이는 가운데에서 5 이상). 숫자는 항상 글자로 보인다. 표 아래 범례에 22개 티어의 곡 점수 기준(0, 12.5, 25 … 225, 237.5, 250, 275~)을 적는다.
- **상세 접기 (2026-10-19)**: `포함 기준` 4카드를 브라우저 기본 `<details>`로 접어 처음엔 닫아 둔다(대부분의 사용자는 한눈에 보기만 읽으면 되도록). 접힌 줄에는 `▸ 포함 기준  상세 설명`(열리면 ▾)을 보인다. 한눈에 보기와 상수표는 접지 않는다.
- **상수표 설명 보강 (2026-10-19)**: 칸 색 설명 아래에 `Gold는 합계 8,000점이라 한 곡당 8,000 ÷ 40 = 200점` 예시를, 참고 카드에 `내부 상수가 4 높은 곡의 S(80%)와 4 낮은 곡의 SS(95%)는 점수가 같습니다`를 더했다(16×4 = 64 = 3.2×20).
- **새 최상위 티어 3개 (2026-10-19, D38)**: 237.5 이상이 한 색이라 구분이 어렵던 문제(예전 빛 6단계)를 티어로 나눠 푼다. **Iridescent(곡 점수 237.5~, 합계 9,500~)** = 예전 하수봉의 기본 무지개(노랑→핑크→보라→청록), **Alien(250~, 10,000~)** = 연두·청록(`#b9f6ca → #22d3ee → #bae6fd`), **HSB(275~, 11,000~)** = 흰빛 + 금색 그라데이션과 바깥 테두리 2px(최대 점수 384까지). 세 티어 칸은 **흰 안쪽 테두리**가 있어 중간 티어(Gold 등)와 갈라 보인다. 글자는 모두 검정이고 숫자가 같이 보이므로 색만으로 전달하지 않는다. 예전의 25점 간격 빛 단계(`data-glow`, `HASUBONG_BAND_*`)는 없앴다. 설명서 상수표 아래 범례는 티어 22개 기준 점수를 한 줄로 적는다. 같은 색 규칙을 레이팅 카드의 곡별 점수 글자와 기록 입력창의 예상 점수에도 쓴다(티어 색은 `globals.css`의 `[data-tier]`, 계산은 `lib/chart-tier.ts`). 티어 구간표(V1 시드 + V10)를 화면에 한 벌 복사해 두므로 ROOT가 구간표를 바꾸면 `lib/chart-tier.ts`도 고친다.
- **레이팅 카드의 곡별 점수**: 오른쪽 점수 숫자를 위 티어 색 글자(`tier-score`)로 그린다. Iridescent 이상은 빛이 더해진다.
- 상수표 설명 아래에 `곡별 레이팅의 최고 수치는 달성률 100%가 아니라 95%입니다. 95%를 넘어도 점수는 더 오르지 않습니다.`를 둔다(수식상 가산점이 95%에서 다 차기 때문). 표 아래 마지막 문장은 `내부 상수는 서열표의 레이팅 상수 난이도로 정해집니다. 이 표는 현재 계수를 기준으로 계산한 값입니다.` 레이팅 반영 스위치(D28)는 설명서에 쓰지 않는다.
- **화면 안내 (2026-10-27)**: `포함 기준` 접기 아래, 점수표 위에 제목 `화면 안내`와 카드 3개(접지 않음): `홈 진행도 카드`(평균 난이도 근처 빈 구간 안내), `"85% 이상이면 레이팅에 반영돼요"란?`(목록이 가득 찼을 때 80·85·90·95% 단위, 단일·그 외 따로, 덜 찼으면 안내 없음), `레이팅 기록`(누를 때만 저장, 하루 한 줄, 같은 날은 덮어씀).
- 상수표 아래 **참고 카드 `참고: 달성률 1%의 점수`**(2026-10-10): 80~95% 구간은 곡과 관계없이 1%마다 약 `4.27점`(= 가산점 3.2 × 20 ÷ 15), 80% 아래는 곡마다 달라 내부 상수 R의 0.2배(R=20이면 정확히 4점). 값은 계수에서 계산해 쓴다(`pointsPerPercentAboveCap`).
- 계수는 `lib/rating-guide.ts`의 기본값(시드와 같은 값)으로 계산한다. 서버 설정 조회 API가 ROOT 전용이라 화면이 설정을 읽지 못한다. 서버 설정을 바꾸면 이 값도 고친다.
- 시안 `Guide-Mobile` / `Main`의 칸 글자색 `#12151C`는 일부 칸에서 대비 4.5에 못 미쳐 코드에서는 `#000`을 쓴다.

## 18. 공지사항 (`/notices`, D30)
- 주 메뉴 `공지`(헤더·모바일 슬라이드 메뉴)로 들어간다. 로그인한 사용자만 본다(로그인 전에는 `공지사항을 보려면 로그인해 주세요.` + 로그인 버튼).
- 제목 `공지사항`. 아래에 **게시판 목록**이 **최근 순**으로 나온다(2026-10-19 개정). 한 줄 = 제목(한 줄, 길면 말줄임) + 오른쪽 작성일(Asia/Seoul, `YYYY-MM-DD`)이고 본문은 목록에 없다. 한 페이지 10건, 아래에 `이전` / `n / m` / `다음`. 줄을 누르면 **상세 페이지 `/notices/{id}`**로 간다(주소가 있어 링크로 공유·뒤로가기가 된다). 상세는 `← 목록으로` + 제목·작성일·본문이고, 본문은 **글자로만** 그리고 줄바꿈은 살린다(HTML은 해석하지 않는다). 없는 공지는 `공지사항을 찾을 수 없습니다.`. 홈의 공지 줄도 해당 상세로 바로 간다.
- 공지가 없으면 `등록된 공지사항이 없습니다.`
- **ADMIN·ROOT에게만**: 맨 위에 `공지 쓰기` 버튼이 있고 누르면 폼(제목 · 내용 · `공지 등록` / `취소`)이 펼쳐진다(2026-10-27부터 처음에는 접혀 있음, 등록하면 다시 접힘), **상세 페이지**에 `고치기` / `삭제` 버튼이 있다(삭제하면 목록으로 이동). `고치기`는 상세가 폼으로 바뀌고(`저장` / `취소`, 저장하면 상세로 돌아옴), `삭제`는 상세 안에 확인(`이 공지를 삭제할까요? 삭제한 공지는 되돌릴 수 없습니다.` + `삭제` / `취소`)이 뜬다. 입력 검사 문구는 `제목을 입력해 주세요.` `내용을 입력해 주세요.`이고, 서버가 거절하면 그 문구를 폼 안에 보이며 입력한 내용은 지우지 않는다.
- 감사 로그 화면(ROOT)의 작업 이름: `공지 등록` `공지 수정` `공지 삭제` `유저 기록 삭제`.

## 19. 마이페이지 (`/me`, D33)
- 메뉴 이름 `마이페이지`(예전 `레이팅`). `/rating`은 `/me`로 이동한다. 로그인 전에는 `내 레이팅과 달성 현황을 보려면 로그인해 주세요.` + 로그인 버튼.
- **통계 탭 맨 위**에 **전체 달성 현황** 카드(레이팅 탭에는 없다): `기록 n/전체`와 EXC / FC / SS / S / S 미만 비율 막대(홈 서열표 진행도와 같은 색, 색 값은 globals.css)와 단계별 개수. 막대는 장식이고 같은 숫자가 글자로 있다. 곡 목록 폴더 API(`/songs/chart-folders`)의 합이다.
- 제목 아래 탭 `레이팅 | 통계`(전체 폭 알약 세그먼트). 선택은 주소(`/me?tab=stats&axis=tier`)에 둔다(기본 레이팅·레벨 폴더는 쓰지 않는다). `레이팅` 탭은 기존 레이팅 화면 그대로(요약, 레이팅 예상 값, 단일 15 / 그 외 25, 레이팅 기록).
- **레이팅 탭 현황 카드 (2026-10-16)**, 요약 카드 바로 아래 · 레이팅 예상 값 위: (1) **기록 제안 배너** — 오늘 아직 기록하지 않았고 마지막 기록과 점수가 다를 때만 나온다(오늘 이미 기록했으면 갱신할 수 있어도 다시 띄우지 않는다. 갱신은 `레이팅 기록`의 버튼에서 한다, 2026-10-27)(`마지막 기록(날짜) 이후 레이팅이 ▲ +33.92 달라졌습니다.` / 기록이 하나도 없으면 `아직 기록한 레이팅이 없습니다.`) + `지금 레이팅 기록하기` 버튼(높이 44px). **자동으로 저장하지 않고 눌러야 남는다(D32)** (2) **요약 한 줄** — `마지막 기록(날짜) 대비 ▲ +33.92 · 새로 들어온 곡 2개`, 누르면 곡별 비교(레이팅 기록의 `비교`와 같은 화면)가 펼쳐진다. **비교 줄의 점수 색 (2026-10-17)**: `30.00 → 35.50 (+5.50)`의 이전·이후 점수는 각각 그 곡 점수의 티어 색(레이팅 곡 카드와 같은 규칙, `lib/chart-tier.ts`)이라 티어가 바뀐 곡은 색으로도 보인다. 숫자와 부호 글자는 그대로 둬서 색만으로 전달하지 않는다. 곡별 상세를 남기기 전의 옛 기록은 비교하지 않고 안내 문구만 보인다(채우지 않는다) (보더 표시와 곧 빠질 곡·목표 문장은 화면이 복잡해서 두지 않는다, 2026-10-16). 모두 이미 받은 레이팅 목록과 비교 API 결과를 맞춰 보는 것이라 새로 저장하는 값이 없다.
- `통계` 탭: 전체 달성 현황 아래에 밑줄 탭 `레벨 폴더 | 서열표 난이도` 중 하나를 고른다. 폴더마다 카드 한 장: 제목(`9.50 ~ 9.99` 또는 `5.8`) · `n개` · `기록 n/전체` · `평균 xx.xx%`(기록이 없어 평균이 없으면 `–`). **평균 계산 토글** `0% 미포함 | 0% 포함`(곡 목록·서열표와 같은 세그먼트, 기본 미포함)은 밑줄 탭 아래에 한 줄로 두고 레벨 폴더·서열표 난이도 두 기준에 함께 적용한다(2026-10-17). 누르면 **달성률 구간 7개**가 펼쳐진다: 95 ~ 100% / 90 ~ 94.99% / 85 ~ 89.99% / 80 ~ 84.99% / 73 ~ 79.99% / 73% 미만 / 미플레이. 줄마다 구간 이름 · 개수 · 비율 막대(막대 색은 SS / S / A / C 단계 색, 미플레이는 회색). **95 ~ 100% 줄의 막대 아래에만** `MAX n` `FC n` 뱃지(0이면 흐리게)를 둔다. 맨 위 요약에는 MAX·FC를 따로 두지 않는다. 0.05 단위는 통계에서 다루지 않는다.
- 폴더 카드 머리: 첫 줄 제목·`n개`·`기록 n/전체`, 둘째 줄 단계 분포 막대(장식)와 오른편에 EXC / FC / SS / S / S 미만 글자 칩(서열표 묶음 머리와 같은 칩, 0개는 흐리게). 구간 줄은 안쪽 상자: 앞에 채운 단계 칩(SS / S / S / S / A / B·C / –), 구간 이름, 오른쪽 `n곡 ›`, 5px 막대. 95~100% 줄 아래 MAX·FC는 왼쪽 띠가 있는 작은 글자 뱃지. 95~100% 줄의 막대는 MAX(EXC) · FC · SS 순으로 단계 색을 나눠 칠한다(칸 너비는 폴더 전체 채보 대비).
- 폴더의 모든 채보를 플레이했고 모두 같은 단계 이상이면 카드 머리가 그 단계(S / SS / FC / EXC) 색으로 밝아지고 왼쪽 띠가 생기며 `전부 SS 이상`처럼 글자가 같이 나온다(`완료` 글자는 쓰지 않는다. 곡 목록·서열표 묶음과 같은 `groupStage` 규칙).
- **데스크톱(1024px 이상) 통계**: 좌우 분할. 왼쪽에 폴더 목록(윗줄 제목 · `n개` · 오른쪽 `평균`, 아랫줄 단계 막대 · 오른쪽 `기록 n/전체`; 글자는 줄바꿈하지 않는다(2026-10-19: 폭 18rem에서 큰 숫자가 줄을 가르던 것을 두 줄 구성으로 바꿈), 10개씩 페이지), 폴더를 누르면 선택 윤곽선이 생기고 오른쪽에 그 폴더의 단계 분포와 달성률 구간 카드(2열)가 나온다. 고르기 전에는 `왼쪽에서 폴더를 선택하면 …` 안내만 보인다. 모바일은 접이식 카드 그대로. 폴더 목록은 두 화면 모두 10개씩 페이지로 나눈다.
- 구간 줄을 누르면 `/me/folder?axis=&key=&bucket=&part=&sort=`로 간다: ← 통계로 · 제목 · `구간 이름 n개`, 파트 칩(전체 / Guitar / Bass), 정렬(레벨 높은 순 / 내 달성률 높은 순 / 낮은 순), 곡 목록과 같은 줄(20개씩 `더 보기`). 곡을 누르면 레벨 폴더는 곡 목록 상세로, 서열표 난이도는 서열표 상세로 간다. 기록이 없는 채보는 달성률 정렬에서 맨 뒤다.
- 기록을 저장·수정·삭제하면 통계 쿼리(`stats`)도 새로 받는다.

## 20. 필터 버튼 (2026-10-13)
- **하나만 고르는 필터 = 세그먼트**: 파트(`전체 | Guitar | Bass`), 평균 계산(`0% 미포함 | 0% 포함`), 통계 구간 목록의 파트. 라벨은 왼쪽에 작게 두고, 오른쪽에 칸이 한 줄로 붙은 작은 상자(`table-head` 바탕, 둥근 모서리 8px, 칸 `px-3 py-1`)를 둔다. 켜진 칸은 `card` 색으로 떠 보이며 **굵은 글씨**와 윤곽(`chip-line`)이 붙는다. 폭은 내용만큼만 차지한다(처음 개편은 전체 폭·36px 높이라 너무 커서 2026-10-13에 줄였다).
- **여러 개 고르는 필터 = 체크 칩**: 추천, 속성, 곡 목록의 난이도. 모서리 6px 작은 사각 칩(`px-2.5 py-1`)이고 켜지면 앞에 **✓**가 붙고 윤곽·연한 배경·글자색이 `check-line` / `check-bg` / `check-fg`(파란 계열)로 바뀐다. 아무것도 고르지 않은 상태가 `전체`이고 `전체` 칩도 같은 모양(켜지면 ✓)이다.
- 켜짐은 색뿐 아니라 굵은 글씨(세그먼트), ✓(체크 칩)로도 보이고 모든 버튼에 `aria-pressed`가 있다. 색 값은 `globals.css` 변수에만 있다(다크 `#6ea0ff`/`#b3c9ff`, 라이트 `#2563eb`/`#1d4ed8`).
- 모바일의 접히는 `필터` 줄(걸린 값 요약)은 그대로 쓴다. 정렬·버전 선택 상자는 이번 개편 대상이 아니다.

## 22. 건의하기 (`/suggestions`, D35)
- 주 메뉴 `건의`로 들어간다. 로그인한 사용자만 본다(로그인 전에는 `건의를 보내려면 로그인해 주세요.` + 로그인 버튼).
- 맨 위에 안내(`하루에 5건까지 보낼 수 있습니다.`)와 `건의 보내기` 폼(종류 선택 · 제목 · 내용 · `건의 보내기`). 종류는 `곡 추가` `개선사항` `버그 제보` `기타`이고 처음 값은 `곡 추가`다. 입력 검사 문구는 `제목을 입력해 주세요.` `내용을 입력해 주세요.`이고, 서버가 거절하면(하루 제한 등) 그 문구를 폼 안에 보이며 입력한 내용은 지우지 않는다. 보내기에 성공하면 제목·내용을 비운다.
- 아래 `내 건의` 카드: 제목 + 작성일(Asia/Seoul) / 종류 + 처리 상태 글자(`접수` `확인 중` `처리 완료` `반려`, 색만으로 구분하지 않는다) / 본문(글자만, 줄바꿈 유지) / 관리자 답변이 있으면 `관리자 답변` 상자. 한 페이지 10건.
- 곡 목록·서열표 검색에서 결과가 없을 때 `찾는 곡이 없나요? 곡 추가 건의하기` 링크가 나오고, 누르면 종류(`곡 추가`)와 제목(검색어)이 미리 채워진 이 화면(`/suggestions?category=SONG_REQUEST&title=…`)으로 온다.
- **요청 채보 (2026-10-20)**: 최근 플레이 가져오기에서 제외된 곡의 `곡 추가 건의하기` 링크는 파트·난이도(`&part=GUITAR&difficulty=MASTER`)도 넘긴다. 폼은 종류가 `곡 추가`일 때 제목 위에 `요청 채보 Guitar | MAS`를 글자로 알리고(고르는 칸이 아니다), 내 건의·관리 카드의 종류 줄에도 같은 표기를 보인다. 종류를 바꾸면 보내지 않는다.
- 관리 건의 카드의 `곡 등록` 버튼(곡 추가 건의에만): 곡 등록 창을 곡명·요청 채보가 채워진 채 연다. 레벨·서열표 값은 관리자가 직접 넣고 확정한다(자동 등록 아님). 등록해도 건의 상태는 자동으로 바뀌지 않는다.
- 관리(ADMIN·ROOT) `/admin/suggestions`: 관리 메뉴의 `건의 관리`로 들어간다. 위에 `접수 대기 n건`, 종류·상태 필터(2026-10-27부터 상태는 처음에 접수 대기가 있으면 `접수 대기`, 없으면 `전체`), 건의 카드(보낸 사람 닉네임 포함)마다 상태 선택 · 답변(선택) · `저장`이 있다. 처리하면 감사 로그에 `건의 처리`로 남는다.

## 23. 세트리스트 (D36)
- **배치 (2026-10-18)**: 모바일·태블릿(lg 미만)은 한 줄로 쌓는다(검색 → 추천 → 내 세트리스트). 데스크톱(lg 이상)은 **두 열**이다: 왼쪽에 곡 검색·내 실력대 추천, 오른쪽에 `완료 n / 전체 m`과 내 세트리스트. 빈 목록 안내의 `위 검색창`은 두 열에서는 왼쪽 검색창을 가리킨다(문구는 그대로 둠).
- **추천 범위 조정 (2026-10-19)**: `내 실력대 추천` 카드의 평균 안내 아래 `범위 조정 ▾`(펼치면 `▴`) 버튼. 펼치면 SS 기준·S 기준 각각 `하위 값 ~ 상위 값` 입력 두 칸(평균 대비 차이, 음수 = 더 쉬운 곡)과 `기본값으로` / `저장`. 형식·범위(−3~+3, 소수 둘째 자리)·하위 ≤ 상위 오류는 입력칸 아래에 글자로 알린다. 저장·기본값으로가 끝나면 접히고 추천이 새로 불러와진다. 직접 정한 범위를 쓰는 중이면 접힌 상태에서 `직접 정한 범위를 쓰고 있습니다.`를 보이고, 기본 범위일 땐 `기본값으로`가 비활성이다. 신규(STARTER)·데이터 부족에는 이 버튼이 없다.
- **속성 표시 (2026-10-24)**: 내 세트리스트 줄과 추천 줄의 `상수 x.x` 옆에 서열표의 속성(단일/복합/이중/삼중/레이팅 제외)을 작은 테두리 칩 글자로 보인다. 글자는 서열표·레이팅 화면의 `patternLabel`을 그대로 쓰고 색으로 구분하지 않는다. 서열표에 없는 채보는 속성을 비운다. **곡 검색 결과 줄에는 보이지 않는다**(곡 목록과 같은 API라 전체 곡 목록은 속성을 보이지 않는다는 9장 규칙을 따른다).
- **곡 검색해서 담기**: 탭 맨 위 카드. 검색창(곡명·아티스트, 입력이 멈추고 0.3초 뒤 검색)과 결과 목록(채보 알약 + `담기` 버튼, 10개씩 `이전 / n / m / 다음`). 이미 담은 채보는 체크 아이콘과 `담김` 글자로 막아 두고(색만으로 구분하지 않는다), 30곡이 차면 모든 `담기`를 막고 안내한다. 담으면 토스트 `세트리스트에 담았습니다.`, 서버가 거절하면 그 문구를 토스트로 보인다. (2026-10-25, D49) **서열표·곡 목록 줄에도 `담기` 글자 버튼**을 둔다(로그인했을 때만, 담긴 채보는 체크 아이콘과 `담김` 글자로 막고 30곡이 차면 모두 막는다; 담기만 하고 빼기는 이 탭에서 한다). 기록 입력 버튼과 헷갈리지 않게 아이콘만 쓰지 않고 글자 버튼으로 하며, 서열표 모바일 카드에서는 오른쪽 끝의 `+`(기록 입력)와 떨어진 채보 줄 끝에 둔다. 데스크톱 곡 목록·서열표는 `달성률` 오른쪽에 64px 칸을 더한다. 곡 상세에는 담기 버튼을 두지 않는다.
- **내 실력대 추천(D37)**: (2026-10-19) `SS 기준`과 `S 기준`은 **각자 자기 `이전 · 1 / n · 다음`** 을 묶음 아래에 둔다(한쪽을 넘겨도 다른 쪽 목록은 그대로). 곡 검색 카드 바로 아래 카드. 맨 위에 `내 평균 난이도 x.x 기준입니다.`, 그 아래 두 묶음 — `SS 기준 (평균 −0.6 ~ −0.1)`과 `S 기준 (평균 −0.1 ~ +0.4)`(범위 숫자는 서버 설정 값, 음수는 평균보다 쉬운 곡; 2026-10-19에 이름과 범위 변경). 줄 = 왼쪽에 곡명 · 채보 알약 · `상수 x.x`, **오른쪽에 내 최고 단계 배지와 달성률(위아래, 오른쪽 정렬; 기록이 없으면 `기록 없음` 글자)과 `담기`/`담김`** (2026-10-19에 단계·달성률을 오른쪽으로 옮김). **순서는 평균 난이도에 가까운 곡이 위**다(D37). 한꺼번에 담는 버튼은 없다. 담으면 추천을 다시 불러와 그 채보가 빠진다. 30곡이 차면 모든 `담기`를 막고 안내한다. 묶음마다 5개씩 같은 쪽으로 `이전 / n / m / 다음`. 묶음이 비면 `추천할 채보가 없습니다.`, 단일/그 외 레이팅 채보가 모자라면 `데이터가 적어 추천하기 어렵습니다. … 단일 3/5곡, 그 외 8/9곡 … 기록을 더 채워 주세요.` 안내만 보이고, 레이팅에 든 기록이 하나도 없는 신규는 `아직 레이팅에 든 기록이 없어 기준 난이도 5.2 이하의 곡을 S 기준으로 보여 드려요.`와 `S 기준 (기준 난이도 5.2 이하)` 묶음만 보인다(SS 기준 없음).
- **마이페이지 `세트리스트` 탭**(주소 `/me?tab=setlist`): 위에 `완료 n / 전체 m (최대 30곡)`과 `완료한 곡 비우기` 버튼(완료한 곡이 없으면 막힘). 줄(카드) = 곡명(곡 상세 링크) · 채보 알약 · `레이팅 상수 난이도 x.x`(미정이면 `미정`) · 내 최고 단계와 달성률 · `완료`(체크 아이콘 + 글자) 또는 `미완료` · `기록 입력`(기존 기록 창) · `빼기`. 10개씩 `이전 / n / m / 다음`.
- 기록을 저장하면 세트리스트 쿼리가 무효화되어 그 줄이 바로 `완료`로 바뀐다. 줄은 지워지지 않는다.
- 비어 있으면 `담은 곡이 없습니다. 위 검색창에서 오늘 칠 곡을 찾아 담아 보세요.`

## 24. 최근 플레이 가져오기 화면 (`/import`, D40)
- 공식 페이지에서 북마크를 누르면 SRPFreaks 창이 열리고(`#srp=...`), 받은 플레이의 **확인·저장·결과가 지금 보던 화면 위의 모달에서 끝난다**(2026-10-19 개정: 화면 이동 없음). `/import`는 **사용 방법 안내만** 보여 준다. 지금은 ROOT만 보이고 일반 사용자는 `이 기능은 아직 준비 중입니다.`.
- **모달**(`ImportHandoff` → `ImportProcessor`, 폭 28rem): 로그인한 사용자는 제목 `받은 플레이 N곡`(오른쪽 `n/4쪽`) + 안내(`아직 저장되지 않았습니다…`) + 칩 + **스크롤되는 곡 목록(최대 20곡)** + 고정 버튼 `취소`(받은 플레이 비움)/`N곡 저장`. 저장하면 같은 모달이 결과(`✓ N곡을 저장했습니다`, 레이팅 변화, `내 기록 보기`/`내 레이팅 보기`/`닫기`)로 바뀐다. 로그아웃이면 `공식 페이지에서 받은 플레이가 있습니다` + `나중에`/`로그인`. **저장 전에 창을 닫거나 브라우저를 종료해도** 받은 플레이는 이 브라우저에 6시간 남아, 홈·마이페이지 등 **어느 화면이든 다음에 열 때 모달이 다시 뜬다**(별도 확인 화면 없음). **저장이 끝난 결과 화면(2026-10-27)**: 1곡 이상 저장했고 기록할 수 있을 때만 `레이팅 변화` 줄 아래에 `지금 레이팅 기록하기`(스냅샷, D32) 버튼이 나온다. 오늘 이미 기록했으면 `오늘 기록 갱신`이고 누르면 오늘 기록을 덮어쓴다(D32 변경, 가져오기를 하루에 여러 번 해도 마지막 상태로 남길 수 있다). 점수가 달라야 하고 자동 저장은 없으며, 누르면 한 번 기록하고 버튼이 사라진다. 기록할 수 없으면(점수 같음·기록 없음) 이유를 따로 적지 않고 버튼을 보이지 않는다.
- **사용 방법**(카드 5개, 시안 확정 2026-10-19): ① `사용하는 환경` 탭 `PC | 모바일`(기본은 터치 기기면 모바일, 아니면 PC) → ② `준비` → ③ `실행 · 매번` → `어떤 기록이 저장되나요?` → `실행 오류`(접이식 4개: 안내 창만 뜸 / 번역 켜짐 / 팝업 차단 / 일부 쪽 실패). 토큰은 필요 없다.
  - **PC 준비(처음 한 번만)**: `SRP 가져오기` 북마크 링크(끌어다 놓기) + `북마크 주소 복사` + **끌어다 놓는 방법 그림**(`bookmark-drag-howto.svg`: ①누른 채로 ②북마크 바까지 끌어서 ③놓기) + 북마크 바가 안 보이면 `Ctrl+Shift+B`(Mac `⌘+Shift+B`) + 북마크 바에 추가된 모습 스크린샷.
  - **모바일 준비**: `실행용 스크립트 복사`(맨 앞 `j`를 뺀 `avascript:…`, 약 300자의 짧은 로더 한 줄. 본체는 해시로 고정한 버전 파일에서 불러온다, D47). 실행 단계에서 주소창을 지우고 `j` 한 글자만 입력한 뒤 붙여넣어 이동하고(주소창 스크린샷), 브라우저가 `javascript:`로 시작하는 붙여넣기 글자의 그 부분을 지우기 때문이라고 설명한다. 일부 앱 안의 브라우저에서는 실행되지 않을 수 있다고 안내한다.
  - **실행(매번)**: 공식 사이트에서 `메인 화면 › 상단 플레이 데이터 › 좌측 슬라이드바 플레이 이력`으로 최근 플레이(stage_result) 페이지를 열고, 그 페이지에서만 북마크(또는 스크립트)를 누른다. 1~4쪽(최대 20곡)을 함께 읽어 오고, 다른 페이지에서는 안내만 뜬다. 이 화면에서 미리보기를 확인·저장한다.
  - **저장 기준**: S.RANDOM+(BUTTON OFF, AUTO OFF)만 / 기존 최고 기록보다 낮으면 건너뜀 / 곡 목록에 없으면 제외되고 필요시 건의하기로 이어짐 / 저장 전 곡마다 체크 해제 가능.
  - **스크린샷**(`public/import-guide/`): 브라우저 주소창·탭만 남기고 사이트 로고·재킷·곡 정보는 자르고, 개인 북마크·프로필·탭 아이콘은 모자이크했다. 일반 `img`(lazy, 폭 100%)와 대체 텍스트를 쓴다.
- **바로가기**: 홈(유저 목록 미리보기 위)과 마이페이지(탭 위)에 `최근 플레이 가져오기` 카드(`ImportEntryLink`)가 `/import`로 연결한다.
- **받은 플레이 목록(모달 안)**: 칩 `✓ 저장 예정` / `건너뜀` / `제외`(곡 목록에 없음, 주황). 줄마다 체크박스(저장 안 하는 줄은 비활성) · 곡명 · `Guitar | MAS` · 안내(`첫 기록` / `새 기록 · 91.20 → 96.50` / `건너뜀 · 기존 기록(94.00)보다 낮음` / `제외 · 곡 목록에 없음` + `곡 추가 건의하기` / `건너뜀 · 지원하지 않는 난이도 (gf_ext)` — 공식 난이도 클래스를 함께 보여 새 난이도 확인에 쓴다) · 오른쪽에 단계 배지와 달성률. 건너뛴 줄은 흐리게.

## 25. 언어 (한국어 · 일본어, D41)
- 헤더 오른쪽(테마 스위치 왼쪽)의 `日本語` / `한국어` 버튼으로 언어를 바꾼다(`LocaleSwitcher`). 버튼에는 **지금 언어가 아닌 쪽의 자기 이름**을 보여 준다(언어를 몰라도 찾을 수 있다). 누르면 쿠키에 저장하고 화면을 새로 받는다(입력 중인 값은 유지된다).
- 첫 방문은 브라우저 언어(일본어면 일본어)로 시작한다. 주소는 언어와 상관없이 같다.
- 글꼴: 본문은 Noto Sans KR 다음에 Noto Sans JP로 넘어간다(`--font-sans`). 일본어 글자가 한글 글꼴에 없을 때 이 글꼴이 쓰인다.
- 곡 제목·아티스트·난이도 표기(MASTER, EXT 등)·`SRN+`·`FC`/`EXC` 같은 표식은 번역하지 않는다.
- 문구는 `frontend/messages/{ko,ja}.json`에 있고 컴포넌트에는 직접 쓰지 않는다. 새 문구를 넣으면 두 파일에 같은 키를 넣는다(테스트가 확인).
- 번역 방식: 컴포넌트는 `useTranslations()`(루트)로 `t("Ns.key")`를 쓴다. 컴포넌트 밖의 도우미 함수는 `t: Translator`를 매개변수로 받고, 표나 상수는 문구 대신 `MessageKey`를 들고 있다가 화면에서 풀어 쓴다. 폼 검사(Zod)는 `makeXxxSchema(t)` 팩토리로 만들어 `useMemo`로 쓴다.
- 컴포넌트 밖에서 만드는 오류 문구(`api.ts`, `google.ts`)는 `Providers`가 등록한 번역기(`i18n/client-messages.ts`)를 쓴다. 서버가 보낸 고정 문구(`ErrorCode`)는 `i18n/server-errors.ts` 표와 같을 때만 번역한다.
- 서버 값(속성 `단일`, 추천도 `상` 등)은 한국어 그대로 주고받고 화면 글자만 `patternLabel`/`recommendLabel`로 바꾼다.
- 번역이 애매한 항목은 `docs/I18N-GLOSSARY.md`에 모은다. 새로 애매한 번역이 생기면 거기에 한 줄 추가한다.

## 26. 공개 준비 화면 (2026-10-21)
- **이용약관** `/terms`: 처리방침과 같은 틀(제목, 시행일, 항목 목록, 문의처). 문구는 `Terms.*`(ko·ja). 법률 검토를 받은 문서가 아니라 초안이며, 실제 동작(탈퇴 즉시 삭제, 운영자의 기록 삭제 D29)과 어긋나지 않게 쓴다. 동작이 바뀌면 약관과 시행일을 같이 고친다. 푸터와 로그인 화면에 링크가 있다.
- **404·오류 화면**: `not-found.tsx`(없는 주소), `error.tsx`(화면 안 오류, 다시 시도 + 홈으로), `global-error.tsx`(맨 바깥 레이아웃 오류, 번역·스타일 없이 한·일 문구를 직접 적음). **오류 내용은 화면에 보이지 않는다.** 이 Next 버전은 다시 시도 함수 이름이 `retry`다.
- **robots.txt·sitemap**: 공개 화면(홈·설명서·처리방침·약관)만 sitemap에 넣고, 로그인 뒤 화면과 `/api`는 robots에서 막는다. 목록은 `lib/site.ts`. 사이트 주소 기본값은 `https://srpfreaks.com`, 다른 주소에서 띄울 때만 `NEXT_PUBLIC_SITE_URL`로 바꾼다(선택).
- **탭 제목**: 곡·유저·공지·건의·설정·마이페이지·로그인·서열표는 `<이름> | SRPFreaks`(`lib/page-metadata.ts`). 링크 공유 미리보기(openGraph)는 제목·설명·사이트 이름만 쓰고 이미지는 쓰지 않는다.

## 27. 공식 곡 목록 갱신 (`/admin/song-import`, D42, ROOT 전용)
- 관리 메뉴의 `공식 곡 목록 갱신` 항목(ROOT만 보임). 화면은 위에서 아래로 **사용 방법 → 받은 곡 → 미리보기 결과 → 반영 결과** 순서다.
- **사용 방법**: 북마크 링크(끌어서 추가)와 `북마크 주소 복사`·`주소창용 코드 복사`(최근 플레이 가져오기와 같은 방식). 북마크는 이어뮤즈먼트 곡 목록 페이지 한 장에서 곡명·아티스트·파트·레벨만 읽어 이 창(`srpfreaks-song-import`)으로 넘긴다. 주소 조각은 `#srpsong=`로, 최근 플레이 가져오기의 `#srp=`와 겹치면 전역 핸드오프가 지워서 다르게 쓴다.
- **받은 곡**: 받은 곡 수, `미리보기`, `비우기`. 받은 곡은 이 화면의 메모리에만 두며 새로 고치면 사라진다. 같은 탭에 쪽을 더 보내면 이어서 쌓인다(같은 줄은 한 번만, 최대 300곡).
- **미리보기 결과**: 읽은 곡·맞은 곡·바뀔 것 없는 곡 수 → `마스터에 없어 제외한 곡`(접어 둔 목록) → `아티스트 채우기`(체크박스, 처음에는 모두 선택) → `레벨 변경`(`곡명 · Guitar MAS · 9.00 → 9.15`, 체크박스) → `아티스트가 달라 건너뛴 곡`(표시만, 체크박스 없음). 미리보기 뒤에 곡이 더 쌓이면 결과를 숨기고 다시 미리보기를 하게 한다.
- `선택한 n건 반영`을 누르면 서버가 차이를 다시 계산해 반영하고, 결과(`아티스트 n건, 레벨 n건을 반영했습니다. (건너뜀 n건)`)를 보여 준 뒤 받은 곡을 비운다. 새 곡·채보는 만들지 않는다.

## 32. 사진으로 입력 (D55, 2026-10-28)

- 위: 제목·안내(고른 사진의 미리보기는 브라우저 안 임시 주소 `blob:`라서 CSP img-src에 blob:을 연다), `사진은 인식에만 쓰고 저장하지 않습니다.`, `이번 주 남은 횟수 n/30`, `사진 고르기 (최대 n장)` 버튼(남은 횟수와 10장 중 작은 값). 고르면 한 장씩 브라우저에서 긴 변 1,024px JPEG로 다시 그려(EXIF 제거) 보내고 `사진을 읽는 중입니다 (k/n)`를 보인다. 한도(429)에 걸리면 남은 사진은 보내지 않는다.
- 위: 제목·안내, `사진은 인식에만 쓰고 저장하지 않습니다.`, `이번 주 남은 횟수 n/30`, `사진 고르기 (최대 n장)` 버튼(남은 횟수와 10장 중 작은 값). 고르면 한 장씩 브라우저에서 긴 변 1,568px JPEG로 다시 그려(EXIF 제거, 950KB가 넘으면 품질을 낮춤) 보내고 `사진을 읽는 중입니다 (k/n)`를 보인다. 한도(429)에 걸리면 남은 사진은 보내지 않는다.
- 확인 목록: 줄마다 사진 미리보기(이 탭의 임시 주소), `사진에서 읽은 곡명`, 채보(정해졌으면 곡명 + 채보 배지 + `다시 고르기`, 아니면 읽은 곡명으로 미리 채운 곡 검색 → `선택`), 달성률(`92.45`·`MAX`, 0.00~100.00, 소수 둘째 자리까지), `Full Combo`, `플레이 날짜`(오늘), SRN+를 확인하지 못했거나 다른 옵션으로 읽혔으면 안내 + `SRN+로 플레이했습니다` 체크(체크해야 저장), `이 기록 저장하기` 체크. 인식에 실패한 사진은 미리보기와 오류 문구만 보인다.
- 아래 고정 줄: `마이페이지로` 링크와 `체크한 기록 저장 (n)` 버튼. 저장은 줄마다 기존 `POST /records`(SRN+)를 부르고, 성공한 줄은 `✓ 저장됨`으로 잠근다. 실패한 줄은 `저장하지 못했습니다. 값을 확인해 주세요.`.


## 33. 라이벌 (D56, 2026-10-31)

시안: 라이벌 시안 캔버스(모바일 7장 + 데스크톱 3장). 7번의 `· 10명`(채보별 인원)과 D4(구간별 랭킹)는 쓰지 않는다.

- **유저 상세** (`/players/{id}`, 로그인했을 때만): 레이팅 카드 아래에 `라이벌 등록`(주 버튼) + `비교`. 등록 뒤에는 `✓ 라이벌`, 서로 등록이면 `✓ 라이벌 · 서로 등록`(체크 색 테두리). 다시 누르면 확인 창 뒤 해제. 아래 줄 `라이벌 n/5명 · 등록해도 상대에게 알리지 않습니다.` 5명이 차면 버튼을 막고 `라이벌은 5명까지 등록할 수 있습니다.` 본인 상세에는 버튼이 없다.
- **마이페이지 `라이벌` 탭**(탭은 `레이팅 | 통계 | 세트리스트 | 라이벌` 4개, 모바일은 탭 좌우 여백 8px): 맨 위 `내 라이벌 n/5`. 카드마다 닉네임 · `서로 라이벌` 칩 · 티어 칩, `총점 · 나보다 ±차이`, 아래 4칸 `승 · 패 · 무 · 상대만`. 카드를 누르면 비교 화면. 비공개가 된 상대는 흐린 카드에 `상대가 기록을 비공개로 바꿨습니다.` + `라이벌 해제`. 비면 `유저 목록에서 공개 유저를 골라 라이벌로 등록할 수 있습니다.`
- **비교** (`/players/{id}/compare`): 머리 3칸 `나 총점 · 승·패·무 · 상대 총점`. 보기 전환 `레이팅 목록 / 곡별 승패`.
  - 레이팅 목록: `단일 / 그 외` 전환, 줄마다 순위 · 곡명(한 줄, 말줄임) · 파트·난이도 알약 · 상대 점수와 달성률 · 내 차이(`1.90↑` 내가 높음, `3.40↓` 낮음, `없음` 내 기록 없음). 화살표 글자로도 구분한다(색만 쓰지 않는다).
  - 곡별 승패: `승 n / 패 n / 무 n / 상대만 n` 전환, 차이 작은 순. 줄마다 곡명 · 알약 · 위 나 / 아래 상대 달성률 · 차이. 20줄씩 `더 보기`. 줄을 누르면 곡 상세.
  - 데스크톱은 머리 3칸을 한 줄에, 목록은 표 모양(곡 · 알약 · 상대 · 나 · 차이).
- **곡 상세 `라이벌 기록` 카드** (로그인 + 라이벌이 있을 때만, 내 기록 카드 아래): 이 채보의 라이벌 줄마다 닉네임 · 달성률 · 차이(내 기준 `+0.30`) · `승/패/무` 글자. 상대 기록이 없으면 `기록 없음`, 내 기록이 없으면 차이 칸을 비운다.
- **알림 종**: 헤더 오른쪽(로그인했을 때만), 안 읽은 개수 배지(9 넘으면 `9+`). 모바일은 아래에서 올라오는 시트, 데스크톱은 종 아래 펼침(380px). 머리 `알림` + `모두 읽음`. 줄: `{닉네임}님이 {곡명} ({파트} {난이도}) 곡을 역전했습니다.` / 묶음 `{닉네임}님이 {n}곡을 역전했습니다.` 아래 작은 글자 `{닉네임} 96.40 · 내 기록 96.10 · 10분 전`(묶음은 `{곡명} 외 n곡 · 오늘`). 안 읽은 줄은 배경 + 점 + `새 알림` 글자. 누르면 읽음 처리 후 비교 화면(곡별 승패)으로. 맨 아래 `알림은 30일 동안 보관됩니다.` 비면 `새 알림이 없습니다.` 개수는 1분마다, 창에 다시 들어올 때 다시 읽는다.
- **설정**: `프로필 공개` 설명을 `공개하면 유저 목록에 닉네임·티어·총점이 보이고, 로그인한 사용자가 레이팅 목록과 곡별 기록을 볼 수 있습니다. 라이벌로 등록될 수 있습니다.`로 바꾸고, 공개 중인 사용자에게 `바뀐 점: 지금까지는 레이팅 목록만 공개됐습니다. 라이벌 기능부터 곡별 기록도 공개됩니다.` 안내를 보인다. 그 아래 `라이벌 알림 받기` 스위치(`서로 라이벌로 등록한 사람이 내 기록을 역전하면 알려 드립니다.`).
- **설명서 `라이벌` 탭**: 설명서 맨 위에 `레이팅 / 라이벌` 탭(주소 `?tab=rival`). 라이벌 탭은 등록 방법, 비교 화면 보는 법, 역전 알림 규칙(서로 등록일 때만, 10분 뒤, 제외 조건, 하루 3건 후 묶음, 30일), 공개 범위, 알림 끄기를 카드로 설명한다.

## 34. 움직임 (D57, 2026-10-31)

사이트 전체를 바꾸지 않고, 열림·나타남에만 짧은 움직임을 둔다. 값과 클래스는 `globals.css`의 "움직임" 블록 한 곳에 있다.

- **원칙**: 120ms(누름) · 180ms(나타남·창) · 240ms(시트). 곡선은 `cubic-bezier(0.2, 0, 0, 1)`(빠르게 시작해 부드럽게 멈춤). 위치(transform)·투명도만 움직이고 크기·배치(높이 펼침 등)는 움직이지 않는다. **닫힘은 움직이지 않고 바로 사라진다**(기다리게 하지 않는다). 숫자 올라가기·화면 전환·목록 순서 바꾸기 같은 움직임은 넣지 않는다.
- **움직임 줄이기**: 기기의 `움직임 줄이기`(prefers-reduced-motion) 설정이면 아래 모두를 끈다(이미 있던 티어 반짝임·스켈레톤과 같은 규칙).
- **적용 위치**
  - 아래에서 올라오는 시트(`motion-sheet`): 하단 탭바 `더보기`, 알림 종(모바일). 넓은 화면(64rem 이상)에서는 같은 요소가 위에서 4px 내려오며 나타난다(알림 종 펼침).
  - 시트 뒤 어두운 영역(`motion-fade`): 서서히 어두워진다.
  - 나타나는 내용(`motion-reveal`, 위에서 4px 내려오며 나타남): 곡 목록 폴더·마이페이지 달성률 폴더·서열표 묶음을 펼칠 때(항상 펼친 묶음은 제외), 서열표 난이도 바로가기, 곡 목록 모바일 필터 패널, 토스트.
  - 창(`<dialog>` 전체): 97% → 100%로 커지며 나타나고 뒤 배경이 서서히 어두워진다(기록 등록·확인 창 등 모든 창 공통).
  - 누름: 버튼을 누르는 동안 98%로 줄어든다(`scale` 속성, 막힌 버튼은 제외).
- 이미 있던 움직임(테마 스위치 손잡이, 스위치 손잡이, 바로가기 화살표 회전, 티어 반짝임)은 그대로 둔다.
