# 운영 메모 (책임자 인수인계용)

대화가 나뉘어도 같은 기준으로 일하려고 정한 운영 규칙과 현재 상태를 적는다. 결정(D번호)은 `DESIGN.md`, 화면 규칙은 `DESIGN-UI.md`, 작업 지시서 양식은 `WORK-ORDER.md`를 따른다. 상태는 날짜를 보고 오래되었으면 GitHub에서 다시 확인한다.

## 작업 규칙 (상시, 2026-11-14 사용자 확정)
되묻는 횟수를 줄이기 위한 규칙이다. 새 대화에서도 그대로 지킨다.

1. **되묻지 않고 진행하는 것**: 새 문구(한국어·일본어), 화면 이름, 배치, 칩 이름, 묶는 기준, 세부 구현 선택.
   - 일본어는 한국어를 뜻에 맞게 옮긴 초안으로 구현하고 「배포 후 검토」로 둔다.
   - 이런 것은 초안으로 구현하고 PR 설명 맨 위에 「결정한 것」 표(항목 / 선택 / 이유 / 바꾸고 싶으면)를 올린다. 사용자는 머지 전에 한 번에 확인하고, 고칠 곳은 후속 커밋으로 처리한다.
2. **구현 전에 멈추고 묻는 것(예외)**:
   - ① 개인정보 처리방침·이용약관 등 법적 문구
   - ② 개인정보에 닿는 집계·노출 범위 변경
   - ③ DB 마이그레이션
   - ④ 배포·롤백·서버 작업
   - ⑤ 이미 확정한 결정(D번호)의 번복
   - ⑥ 사용자가 「먼저 확인」이라고 적은 항목
3. **절차 질문**(기존 PR이 있는지, 번호, 브랜치 상태)은 작업자가 GitHub에서 직접 확인하고 묻지 않는다.
4. **질문이 꼭 필요하면** 한 번에 모아서, 각 질문마다 권고 답을 붙여 올린다(사용자가 「권고대로」라고만 답할 수 있게).

## 사용자 작업 방식 (지킬 것)
- **시안이 있을 때**는 시안을 기준으로 구현하고, 큰 UI 변경 PR은 시안을 봤는지 확인한다. 시안이 없는 화면 문구·배치·칩 이름은 위 「작업 규칙」대로 초안으로 구현하고 PR 설명의 「결정한 것」 표로 확인받는다.
- 디자인·UX/UI 개선과 아이디어가 있으면 먼저 제안한다.
- 마이그레이션이 든 큰 작업이 예상되면 시작 전에 사용자에게 먼저 알린다(CLAUDE.md "책임자 운영 방식").
- 한국어로 짧게 쓰고, 끝에 상태 표(항목 / 상태 / 막힌 이유 / 필요한 답)를 붙인다. 사용자가 정한 문구는 임의로 다듬지 않는다.
- 사용자는 토큰이 부족하다. 큰 기능은 새 대화에서 하고, 작업은 작업자(서브에이전트)에게 시킨다.
- 공개 저장소이므로 보안 취약점 내용은 PR·이슈·커밋·문서 어디에도 쓰지 않는다. 비밀값·개인정보·로그 원문도 쓰지 않는다.
- 사이트 설정 변경은 사용자(ROOT)가 직접 한다. 자동 백업(.sql.gz)은 지우지 않는다. force push 금지, squash 머지만 쓴다.

## 6시 머지·배포 (매일 06:00 KST 예약 작업)
- 대상은 `6시 머지` 라벨이 붙은 열린 PR이다. 라벨이 없으면 머지하지 않는다. PR 번호가 작은 것부터, 본문에 "#번호 위에 쌓은"이라고 적힌 PR은 그 PR이 머지된 뒤에 한다.
- 브랜치 갱신(update-branch)은 하지 않는다(main은 최신 브랜치 필수가 아님). 충돌(dirty)이면 건너뛰고 이유를 보고한다. CI가 실패하면 실패한 작업만 한 번 다시 돌리고, 그래도 실패면 건너뛴다.
- **마이그레이션(`backend/src/main/resources/db/migration/`)이 바뀐 PR은 자동 머지하지 않고** "사용자 확인 필요"로 남긴다. 운영 반영 전에 백업 복구 연습(Server Ops)을 한다.
- **6시 예약 작업은 배포하지 않는다**(2026-11-03 확인: 자동 작업의 권한 검사가 운영 배포를 거부한다). 머지 뒤 보고에 "배포 대기(대상)"만 남기고, 사용자가 대화에서 "배포해줘"라고 승인하면 책임자 대화가 Deploy 워크플로를 한 번 실행한다. `backend/` 파일이 머지됐으면 "frontend + backend", 아니면 "frontend". 배포 뒤 화면 자동 확인(D59, 360·1280px) 결과를 보고한다. 실패해도 되돌리지 않고 사실과 링크만 보고한다.
- 서버 중지, DB 작업, 백업 복구, nginx 재시작은 예약 작업이 하지 않는다. 결과는 06:30 KST에 보고 작업이 알린다(안 끝났으면 10분 뒤 다시 확인). 서버 중지, DB 작업, 백업 복구, nginx 재시작은 예약 작업이 하지 않는다.
