# 작업 지시서 양식

## 역할 나누기 (2026-11-03)
- **상담·시안 대화:** 사용자와 아이디어, 시안, 방향을 정한다. 끝나면 아래 "결정 메모"를 한 덩어리로 만들어 준다.
- **관리자 대화(Claude Code):** 사용자가 결정 메모를 **한 번 붙여넣으면** 작업 지시서로 바꾸고, 작업자에게 맡기고, PR을 검토하고, 머지·배포 승인을 사용자에게 묻는다.
- **작업자:** 지시서대로 구현하고 4가지(바뀐 파일 / 테스트 결과 / 문서 갱신 여부 / 막힌 점)만 보고한다.
- 상태와 일정은 `docs/OPS-NOTES.md`와 PR 본문에만 적는다. 라벨 붙이기, "배포해줘", 마이그레이션 확인은 사용자가 답한다.

## 결정 메모 (상담 대화가 만들어 주는 붙여넣기용)
```
작업 이름: (한 문장)
결정: (선택한 안, 시안 파일 이름과 안 번호)
바꿀 곳: (화면/파일)
지킬 것: (사용자가 정한 문구, 바꾸지 말 것)
마이그레이션: 없음 / 있음
```
관리자는 이 메모를 아래 양식으로 펼쳐 작업자에게 준다.


책임자가 작업자(서브에이전트 또는 별도 대화)에게 일을 맡길 때 이 양식을 채운다. 작업자는 이전 대화를 보지 못하므로 아래를 빠짐없이 적는다.

```
## 작업 이름
(한 문장. 기능 하나만)

## 배경과 목표
- 왜 필요한가, 사용자가 확정한 결정(시안 이름, 동작 방식)

## 바꿀 곳
- 파일/폴더, 새로 만들 파일
- 건드리지 말 것

## 지켜야 할 규칙
- CLAUDE.md의 관련 절(예: 보안, 스킬 계산, 프론트 규칙)
- 문구는 사용자가 정한 대로 쓰고 임의로 다듬지 않는다
- 요청하지 않은 리팩터링·의존성 추가 금지

## 마이그레이션
- 없음 / 있음(번호, 내용). 있으면 사용자 확인이 끝났는지 적는다

## 테스트
- 같이 작성할 테스트, 직접 계산한 예시값

## 문서
- 고칠 문서(DESIGN.md 결정 번호·변경 이력, DESIGN-UI.md, CLAUDE.md)

## 끝났을 때 보고 (4가지)
1. 바뀐 파일
2. 테스트 결과
3. 문서 갱신 여부
4. 막힌 점
```

PR은 기능 하나당 하나, 초안(draft)으로 올린다. 마이그레이션이 든 PR은 6시 자동 머지에서 빠지고 사용자 확인을 받는다.
